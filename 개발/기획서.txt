# BLANKSPACE
## 전체 사이트 기획서 v1.0
**A Creative Workspace for Creators**

---

# 0. 프로젝트 개요

## 0-1. 프로젝트 명칭

- 프로젝트명: Blankspace
- 서비스 유형: 개인 창작 작업 공간
- 주요 대상: 게임 기획자, 작가, 일러스트레이터, 3D 아티스트, 세계관 창작자 등
- 핵심 방향: 문서 제작 + 위키 및 정보 연결 + 시각화 도구 + 창작 자료 관리

## 0-2. 프로젝트 목적

Blankspace는 창작에 필요한 정보와 자료를 한곳에서 관리하고, 사용자가 자신의 작업 방식에 맞게 작업 환경을 구성할 수 있도록 지원하는 개인 창작 작업 공간이다.

단순한 문서 작성 프로그램이 아니라 다양한 형태의 콘텐츠를 만들고 서로 연결할 수 있는 통합 환경을 제공한다.

사용자는 Blankspace에서 다음 작업을 수행할 수 있다.

- 캐릭터와 세계관 설정 정리
- 게임 기획 및 시스템 설계
- 문서 작성 및 편집
- 캐릭터 관계도와 세계 지도 제작
- 타임라인 및 게임 플로우 구성
- 이미지, 영상, 오디오 등 레퍼런스 관리
- 모델링 및 애니메이션 자료 정리
- 프로젝트별 자료 관리
- 문서 간 연결 및 정보 탐색
- 자신만의 템플릿과 작업 환경 제작

## 0-3. 핵심 설계 원칙

| 원칙 | 설명 |
|---|---|
| 자유도 | 사용자가 원하는 방식으로 문서와 작업 공간 구성 |
| 모듈화 | 각 기능을 독립적인 시스템으로 설계 |
| 재사용성 | 컴포넌트와 기능을 여러 템플릿에서 공유 |
| 연결성 | 문서와 자료 사이의 관계를 연결 |
| 확장성 | 새로운 템플릿과 기능을 추가하기 쉬운 구조 |
| 안정성 | 기존 데이터와 사용자 작업 내용 보존 |

# 1. 전체 시스템 아키텍처

Blankspace는 다음 8가지 핵심 시스템을 기반으로 구성한다.

1. 공간 관리 시스템
2. 문서 관리 시스템
3. 템플릿 시스템
4. 컴포넌트 시스템

각 시스템은 독립적인 역할을 가지지만 서로 연동되어야 한다.

# 2. 공간 관리 시스템 (Workspace & Project)

## 2-1. Workspace

Blankspace는 단일 Workspace 구조를 사용한다.

Workspace는 사용자의 전체 작업 환경이며, 그 안에서 여러 프로젝트를 생성하고 관리한다.

기본 규칙:
- Workspace는 하나만 존재한다.
- Workspace 생성 및 전환 기능은 제공하지 않는다.
- 여러 프로젝트를 생성할 수 있다.
- 모든 프로젝트는 동일한 Workspace에 속한다.
- 휴지통은 Workspace 전체에서 하나로 관리한다.

## 2-2. Project

프로젝트는 하나의 창작 활동이나 작업 단위를 관리하는 공간이다.

예시:
- 게임 개발 프로젝트
- 세계관 제작 프로젝트
- 개인 캐릭터 창작 프로젝트
- 포트폴리오 프로젝트

기본 기능:
- 프로젝트 생성
- 프로젝트 삭제
- 프로젝트 이름 변경
- 프로젝트 설명 수정
- 프로젝트 아이콘 설정
- 프로젝트 커버 이미지 설정
- 프로젝트 색상 설정
- 프로젝트 즐겨찾기
- 프로젝트 정렬
- 프로젝트 복제

### 프로젝트 복제

프로젝트 복제는 완전 복제를 지원한다.

복제 대상:
- 프로젝트 정보
- 폴더 및 하위 폴더 구조
- 모든 문서
- 문서 내부 콘텐츠
- 컴포넌트 구성
- 디자인 및 스타일
- 이미지와 첨부 파일
- 기타 프로젝트 설정

데이터 규칙:
- 복제 프로젝트는 새로운 Project ID를 가진다.
- 모든 폴더와 문서는 새로운 ID를 가진다.
- 복제 프로젝트 내부의 문서 링크는 복제본 내부의 대응 문서를 연결한다.
- 원본 프로젝트는 영향을 받지 않는다.
- 생성 날짜와 수정 날짜는 복제 시점에 맞게 기록한다.

## 2-3. Folder

폴더는 프로젝트 내부 자료를 분류하는 기능이다.

폴더 구조:
- 프로젝트 최상위에 폴더 생성 가능
- 폴더 내부에 하위 폴더 생성 가능
- 하위 폴더 깊이 제한 없음
- 폴더 내부에 문서 생성 가능
- 같은 폴더 안에 문서와 하위 폴더 혼합 가능

기본 기능:
- 폴더 생성 및 삭제
- 폴더 이름 변경
- 폴더 아이콘 변경
- 폴더 커버 이미지 설정
- 폴더 색상 변경
- 폴더 이동
- 폴더 복제
- 폴더 정렬
- 접기 및 펼치기
- 폴더 경로 표시

### 폴더 삭제

폴더 삭제 시 내부에 포함된 모든 자료를 함께 휴지통으로 이동한다.

삭제 대상:
- 해당 폴더
- 모든 하위 폴더
- 하위 폴더 내부의 문서
- 해당 폴더에 포함된 기타 자료

삭제 시 기존 구조와 위치 정보를 보존한다.

복원 시 원래 구조로 복원한다.

## 2-4. Document 위치

문서는 프로젝트 최상위 또는 프로젝트 내부 폴더에 생성할 수 있다.

```text
Project
│
├── Project Overview (Document)
├── Development Notes (Document)
│
├── Character (Folder)
│   ├── Character A (Document)
│   └── Character B (Document)
│
└── World (Folder)
    ├── World Sheet (Document)
    └── World Map (Document)
```

문서와 폴더는 같은 위치에 함께 존재할 수 있다.

# 3. 문서 관리 시스템 (Document)

문서는 Blankspace에서 실제 작업이 이루어지는 기본 단위다.

## 3-1. 문서 유형

문서 생성 시 다음 세 가지 유형을 선택한다.

### A. 템플릿 문서

미리 정의된 템플릿을 기반으로 생성한다.

예시:
- 캐릭터 시트
- 세계관 시트
- 관계도
- 지도
- 타임라인
- 게임 기획서

템플릿에 정의된 기본 구조와 컴포넌트를 사용한다.

### B. 빈 문서

일반적인 워드 프로세서 형태의 문서다.

기본 기능:
- 자유로운 텍스트 작성
- 제목과 본문
- 문단 및 텍스트 서식
- 이미지 삽입
- 기본적인 문서 편집

자유롭게 요소를 배치하는 캔버스 방식은 사용하지 않는다.

### C. 자유 작업 문서

일반적인 문서 흐름에서 벗어나 자유롭게 자료를 배치하는 작업 공간이다.

대표 예시:
- 메모
- 자유 캔버스
- 참고 자료 보드

지원 요소는 문서 종류에 따라 구분한다.

예를 들어 메모에서는 다음을 지원한다.
- 텍스트
- 이미지
- 영상
- 오디오
- YouTube 미리보기
- 자유로운 배치
- 그림 및 드로잉

## 3-2. 문서 공통 속성

모든 문서 유형은 다음 속성을 공통적으로 가진다.

| 속성 | 설명 |
|---|---|
| 문서 이름 | 문서 제목 |
| 문서 아이콘 | 문서 대표 아이콘 |
| 커버 이미지 | 문서 대표 이미지 |
| 문서 설명 | 문서에 대한 간단한 소개 |
| 생성 날짜 | 최초 생성 시점 |
| 수정 날짜 | 마지막 수정 시점 |
| 즐겨찾기 | 자주 사용하는 문서 표시 |
| 태그 | 문서 분류 |
| 문서 유형 | 템플릿 / 빈 문서 / 자유 작업 |
| 소속 위치 | 프로젝트 및 폴더 정보 |

아이콘과 커버 이미지는 각각 독립적으로 설정할 수 있다.

## 3-3. 문서 관리 기능

- 문서 생성
- 문서 삭제
- 문서 이름 변경
- 문서 아이콘 변경
- 커버 이미지 변경
- 문서 설명 수정
- 문서 이동
- 문서 복제
- 문서 즐겨찾기
- 문서 정렬
- 문서 검색
- 문서 태그 관리

### 문서 이동 규칙

문서는 동일한 프로젝트 내부에서만 이동할 수 있다.

가능한 이동:
- 프로젝트 최상위 → 폴더
- 폴더 → 프로젝트 최상위
- 폴더 A → 폴더 B
- 하위 폴더 간 이동

다른 프로젝트로 직접 이동하는 기능은 제공하지 않는다.

이동 시 문서 ID와 기존 내부 링크를 유지한다.

### 문서 복제 규칙

문서 복제는 완전 복제를 지원한다.

복제 대상:
- 문서 유형
- 템플릿 구조
- 컴포넌트 구성
- 컴포넌트 내부 콘텐츠
- 이미지 및 미디어
- 디자인 설정
- 스타일
- 태그 및 설명

복제본은 새로운 문서 ID를 가진다.

복제본을 수정해도 원본에는 영향을 주지 않는다.

내부 문서 링크는 기본적으로 원본 문서를 참조한다. 단, 프로젝트 전체 복제처럼 내부 참조 대상을 함께 복제하는 작업에서는 복제본 내부의 대응 문서로 연결한다.

# 4. 휴지통 시스템 (Trash)

Workspace 전체에서 하나의 통합 휴지통을 사용한다.

## 4-1. 관리 대상

- 삭제된 프로젝트
- 삭제된 폴더
- 삭제된 하위 폴더
- 삭제된 문서
- 기타 삭제된 자료

## 4-2. 기본 기능

- 삭제 날짜 표시
- 원래 소속 프로젝트 표시
- 원래 폴더 경로 표시
- 개별 복원
- 여러 항목 일괄 복원
- 영구 삭제
- 휴지통 비우기
- 삭제된 폴더의 하위 구조 확인

## 4-3. 삭제 및 복원 규칙

삭제된 자료는 즉시 영구 삭제하지 않는다.

복원 시:
- 원래 Project ID 유지
- 원래 Folder ID 유지
- 원래 Document ID 유지
- 기존 위치 복원
- 기존 내부 링크 유지

원래 위치가 존재하지 않는 경우 복원 위치를 지정하도록 한다.

## 4-4. 삭제된 문서와 내부 링크

삭제된 문서를 참조하는 다른 문서의 링크는 삭제하지 않는다.

상태별 동작:

| 문서 상태 | 링크 동작 |
|---|---|
| 정상 | 정상적으로 문서 열기 |
| 휴지통 | 삭제된 문서임을 표시 |
| 영구 삭제 | 영구 삭제된 문서임을 표시 |
| 복원 | 기존 링크 정상 작동 |

# 5. 템플릿 시스템 (Template)

템플릿은 문서 생성 시 기본 구조를 제공하는 시스템이다.

템플릿은 실제 문서 콘텐츠와 분리하여 관리한다.

## 5-1. 템플릿 분류

### 캐릭터

- 캐릭터 시트
- 캐릭터 관계도
- 캐릭터 문답

### 세계관

- 세계관 시트
- 지도
- 타임라인
- 용어집

### 게임 기획

- 게임 기획서
- 게임 플로우
- UI/UX
- 아이템 및 장비
- 게임 대화 스크립트

### 디자인 및 에셋

- 레퍼런스 보드
- 모델링 시트
- 애니메이션 시트
- 사운드보드

### 일반

- 빈 문서
- 메모
- 일정
- 파일 보관함

기존에 논의된 템플릿 분류를 기준으로 하며, 새로운 템플릿은 향후 추가할 수 있다.

## 5-2. 기본 템플릿과 사용자 템플릿

Blankspace는 기본 템플릿과 사용자 템플릿을 모두 제공한다.

### 기본 템플릿 수정

사용자는 기본 템플릿을 직접 수정할 수 있다.

수정 가능한 요소:
- 컴포넌트 추가 및 삭제
- 컴포넌트 순서 변경
- 컴포넌트 크기 및 위치
- 컴포넌트 스타일
- 기본 필드
- 기본 레이아웃

기본 템플릿을 원래 상태로 복원하는 기능도 제공한다.

### 사용자 템플릿 제작

두 가지 제작 방식을 지원한다.

1. 기존 템플릿을 복제하여 수정
2. 빈 템플릿부터 직접 제작

사용자 템플릿 관리:
- 템플릿 생성
- 이름 및 설명 변경
- 아이콘과 커버 설정
- 복제
- 삭제
- 분류
- 태그
- 미리보기
- 기본 템플릿으로 지정

템플릿에는 실제 문서 콘텐츠를 저장하지 않는다.

템플릿은 컴포넌트 구성과 기본 스타일을 보유하고, 실제 문서 데이터는 별도로 관리한다.

기존 문서의 콘텐츠는 템플릿 수정으로 인해 변경되지 않아야 한다.

## 5-3. 디자인 프리셋과 사용자 템플릿 구분

두 기능은 별개로 관리한다.

**디자인 프리셋**
- 시각적 스타일만 저장
- 레이아웃과 배치
- 크기 및 간격
- 색상
- 테두리
- 글꼴과 타이포그래피
- 이미지 영역

**사용자 템플릿**
- 컴포넌트 구조
- 사용자 지정 필드
- 기본 콘텐츠 구조
- 레이아웃
- 디자인 스타일

디자인 프리셋은 실제 콘텐츠를 저장하지 않는다.

# 6. 컴포넌트 시스템 (Component)

컴포넌트는 문서 내부를 구성하는 독립적인 요소다.

캐릭터 시트와 세계관 시트는 동일한 컴포넌트 편집 시스템을 사용한다.

컴포넌트 라이브러리는 공통으로 관리하고, 템플릿마다 기본 추천 및 배치 구성을 다르게 제공한다.

## 6-1. 공통 컴포넌트 (13종)

| 컴포넌트 | 기능 |
|---|---|
| 이미지 카드 | 단일 이미지 삽입 |
| 이미지 갤러리 | 여러 이미지 모음 |
| 텍스트 카드 | 짧은 텍스트 |
| 서술 카드 | 긴 글 및 문단 작성 |
| 세부사항 카드 | 사용자 지정 항목과 값 |
| 태그 카드 | 키워드 분류 |
| 인용 카드 | 문구 및 인용문 강조 |
| 표 카드 | 행과 열로 정보 정리 |
| 컬러 팔레트 | 색상 및 코드 관리 |
| 문서 링크 카드 | 내부 문서 연결 |
| 동영상 카드 | 영상 URL 및 미리보기 |
| 오디오 카드 | 오디오 파일 재생 |
| 메모 카드 | 자유로운 메모 작성 |

## 6-2. 캐릭터 특화 컴포넌트 (3종)

### 프로필 카드
- 대표 이미지
- 캐릭터 이름
- 별명
- 간단한 소개

### 스탯 카드
- 숫자형
- 막대그래프형
- 레이더 차트형
- 항목과 수치 사용자 지정

### 관계 요약 카드
- 다른 캐릭터 문서 연결
- 관계 이름
- 관계 설명
- 여러 관계 추가

전체 관계를 시각화하는 관계도 템플릿과는 구분한다.

## 6-3. 세계관 특화 컴포넌트 (3종)

### 계층 구조 카드
- 상위 및 하위 항목
- 조직 구조
- 영역 및 계급 구조
- 트리 형태 표시

### 분류 목록 카드
- 사용자 지정 분류
- 분류별 항목
- 하위 항목
- 설명 및 순서 변경

### 구역 카드

세계관 내부의 특정 구역에 어떤 장소가 존재하는지 정리하는 컴포넌트다.

기본 형태:

```text
구역

[ A ] [ B ] [ C ] [ + ]

뫄뫄   봐봐   솨솨
```

기능:
- 구역 제목 설정
- 장소 추가 및 삭제
- 장소 이름 수정
- 순서 변경
- 아이콘 또는 이미지 설정
- 내부 문서 연결
- 문서 연결 해제

문서가 연결된 장소는 버튼 형태로 표시한다.

버튼 클릭 시 연결된 내부 문서로 이동한다.

문서가 연결되지 않은 장소도 이름만 등록할 수 있다.

구역 카드는 지도 템플릿을 대체하지 않는다. 장소의 존재와 상세 문서 연결을 담당한다.

## 6-4. 레이아웃 요소 (4종)

| 요소 | 기능 |
|---|---|
| 섹션 제목 | 제목 및 소제목 |
| 구분선 | 영역 구분 |
| 여백 | 간격 조절 |
| 그룹 컨테이너 | 여러 컴포넌트 묶기 |

## 6-5. 컴포넌트 편집 기능

- 추가 및 삭제
- 복제
- 이름 변경
- 위치 이동
- 크기 변경
- 내부 항목 추가 및 삭제
- 순서 변경
- 스타일 수정

스타일 설정:
- 배경색
- 테두리
- 모서리
- 내부 여백
- 글자 크기
- 글자 색상
- 정렬
- 표시 방식

각 컴포넌트의 특성에 맞는 편집 기능만 제공한다.

## 6-6. 템플릿별 컴포넌트 기본 구성

캐릭터 시트 기본 추천:
- 프로필 카드
- 이미지 카드
- 이미지 갤러리
- 텍스트 카드
- 서술 카드
- 세부사항 카드
- 태그 카드
- 스탯 카드
- 관계 요약 카드

- 컬러 팔레트
- 메모 카드

세계관 시트 기본 추천:

- 텍스트 카드

- 태그 카드
- 인용 카드
- 표 카드
- 컬러 팔레트
- 문서 링크 카드
- 계층 구조 카드
- 분류 목록 카드
- 구역 카드
- 메모 카드

특화 컴포넌트도 다른 템플릿에서 필요하면 사용할 수 있도록 한다.

# 7. 시각화 도구 시스템 (Visual Tools)

일반 문서와는 다른 편집 방식을 제공하는 독립적인 작업 도구다.

## 7-1. 캐릭터 관계도

캐릭터 간 관계를 시각적으로 표현하는 도구다.

기본 기능:
- 캐릭터 노드 생성
- 캐릭터 문서 연결
- 캐릭터 이미지 표시
- 노드 자유 이동
- 관계선 생성 및 삭제
- 관계 이름 설정
- 관계선 방향 설정
- 관계선 색상 변경
- 관계선 종류 변경
- 관계선 굵기 변경
- 확대 및 축소
- 캔버스 이동

관계선 스타일:
- 단색
- 2색 그라데이션
- 다중 색상 그라데이션
- 그라데이션 방향 변경
- 색상 정지점 추가 및 삭제
- 실선
- 점선
- 파선

관계 범례:
- 관계 유형 추가 및 삭제
- 이름 변경
- 순서 변경
- 색상 변경
- 선 스타일 설정
- 범례 표시 및 숨김
- 해당 관계 유형 강조 표시

범례에서 설정한 스타일은 같은 유형의 관계선에 기본 적용한다.

개별 관계선은 별도 스타일로 덮어쓸 수 있다.

동일한 캐릭터 두 명 사이에 여러 종류의 관계를 연결할 수 있다.

## 7-2. 지도

세계관의 지역 및 장소를 시각적으로 관리한다.

기본 방향:
- 지도 이미지 등록
- 지도 위 자료 배치
- 지역 및 장소 표시
- 지도 요소와 문서 연결
- 관련 문서 열기
- 지도 이미지 교체
- 확대 및 축소
- 자유로운 위치 조정

지도는 세계관 시트의 구역 카드와 연동할 수 있도록 설계한다.

구역 카드가 장소 목록과 문서 연결을 담당한다면 지도는 공간적인 위치와 관계를 표현한다.

## 7-3. 타임라인

세계관 또는 게임의 시간적 흐름을 표현한다.

기본 방향:
- 사건 생성
- 사건 이름과 설명
- 날짜 또는 시점 지정
- 사건 순서 변경
- 이미지 첨부
- 관련 문서 연결
- 시간 단위 설정
- 확대 및 축소

구체적인 시간축 표현과 편집 방식은 별도 UI 설계 단계에서 확정한다.

## 7-4. 게임 플로우

게임의 진행 흐름과 시스템 구조를 노드 형태로 설계한다.

기본 방향:
- 노드 생성
- 노드 이동
- 노드 연결
- 연결선 변경
- 노드 설명 입력
- 노드 삭제 및 복제
- 화면 확대 및 축소
- 흐름 구조 저장

구체적인 노드 유형과 연결 규칙은 별도 설계한다.

# 8. 연결 및 탐색 시스템 (Connection)

Blankspace의 모든 문서와 자료를 서로 연결하는 시스템이다.

## 8-1. 내부 링크

- 다른 문서 검색
- 문서 연결
- 연결된 문서 이름 표시
- 링크 클릭으로 문서 열기
- 링크 변경 및 해제
- 삭제된 문서 상태 표시

## 8-2. 역링크

다른 문서에서 현재 문서를 참조하는 목록을 확인할 수 있도록 한다.

표시 정보:
- 참조한 문서 이름
- 참조 위치
- 문서 유형
- 참조 상태

## 8-3. 문서 관계

문서 간 연결 관계를 관리한다.

활용 예시:
- 캐릭터 문서와 세계관 문서 연결
- 지역 문서와 지도 연결
- 아이템 문서와 게임 시스템 문서 연결
- 타임라인 사건과 관련 문서 연결

문서 연결은 실제 콘텐츠를 복사하는 것이 아니라 참조 관계를 유지하는 방식으로 설계한다.

## 8-4. 검색

검색 대상:
- 프로젝트
- 폴더
- 문서 이름
- 문서 설명
- 태그
- 문서 내부 콘텐츠
- 연결된 자료

구체적인 검색 필터와 검색 UI는 추후 확정한다.

# 9. 디자인 및 사용자 지정 시스템 (Customization)

Blankspace는 고정된 문서 양식에 사용자를 맞추는 것이 아니라 사용자가 자신의 작업 방식에 맞춰 환경을 구성하는 것을 목표로 한다.

- 기본 템플릿 수정

- 기존 템플릿 복제
- 빈 템플릿 생성
- 원본 기본 템플릿 복원

## 9-3. 디자인 프리셋

디자인 프리셋은 시각적 설정만 저장한다.

저장 대상:
- 컴포넌트 배치
- 크기
- 간격
- 색상
- 배경
- 테두리
- 글꼴
- 이미지 영역

지원 기능:
- 생성
- 이름 변경
- 복제
- 삭제
- 적용
- 기본값 복원

디자인 프리셋과 사용자 템플릿은 별도로 관리한다.

## 9-4. 테마

기존에 논의한 기본 테마 방향:
- 라이트 모드
- 다크 모드

다크 모드는 메인 화면뿐 아니라 모든 템플릿과 편집 요소에 일관되게 적용해야 한다.

- 일반 파일
- 문서 첨부 자료

파일은 실제 문서 데이터와 구분하여 관리하되, 문서와의 연결 관계를 보존한다.

파일이 참조되는 동안 임의로 삭제하지 않는다.

## 11-5. 백업 및 복구

- 데이터 백업
- 데이터 복원
- 파일 보존
- 구조 변경 전 백업
- 데이터 마이그레이션
- 오류 발생 시 복구

구체적인 백업 방식과 저장 위치는 기술 설계 단계에서 확정한다.

- 사용자가 쉽게 이해할 수 있는 도움말

# 13. 도움말 시스템

Blankspace의 각 기능은 실제 구현 상태에 맞는 도움말을 제공한다.

도움말에 포함할 내용:

기능이 준비되지 않은 경우 준비 중이라고 표시한다.

# 14. 개발 및 유지보수 원칙

## 14-1. 기존 데이터 보호

보존 대상:

- 문서
- 문서 ID
- 컴포넌트 ID

- 파일

공통 컴포넌트는 중복 구현하지 않고 공유 라이브러리를 사용한다.

# 16. 최종 개발 기준

Blankspace 개발 시 다음 원칙을 반드시 준수한다.

1. 전체 시스템 구조를 먼저 이해하고 개발한다.
2. 기능을 추가하기 전에 기존 기능과 중복되는지 확인한다.
3. 기존 사용자 데이터를 임의로 삭제하거나 변경하지 않는다.
4. 템플릿과 실제 문서 콘텐츠를 분리한다.
5. 컴포넌트는 공통 라이브러리로 관리한다.
6. 시각화 도구는 독립적인 편집 시스템으로 설계한다.
7. 보기 모드와 편집 모드의 권한을 엄격하게 구분한다.
8. 모든 주요 작업은 저장 및 복원 가능해야 한다.
9. 기능 구현 후 실제 브라우저 테스트를 진행한다.
10. 미구현 기능을 구현 완료로 표시하지 않는다.
11. 기존 UI와 사용 흐름을 임의로 변경하지 않는다.
12. 데이터 구조 변경은 영향 분석과 백업 후 진행한다.
13. 작업은 단계별로 진행하고 각 단계가 끝나면 결과를 보고한다.
14. 사용자 승인 없이 다음 단계의 대규모 변경을 진행하지 않는다.

| 검색 | 검색 필터 및 검색 범위 |
| 파일 시스템 | 저장 위치 및 파일 관리 방식 |
| 백업 | 백업 방식과 복구 절차 |
| 지도 | 지도 편집 UI와 마커 기능 |
| 타임라인 | 시간축과 사건 배치 방식 |
| 게임 플로우 | 노드 종류와 연결 규칙 |
| 관계도 | 세부 편집 및 상호작용 |
| 사용자 템플릿 | 공유 및 가져오기 정책 |
| 디자인 프리셋 | 지원 템플릿과 적용 규칙 |
| 계정 및 배포 | 사용자 인증 및 운영 방식 |

위 항목은 임의로 확정하지 않고 별도의 설계 과정을 거친다.

# 18. 프로젝트 최종 목표

Blankspace는 사용자가 자신의 창작 활동을 한곳에서 관리하고, 필요한 도구를 직접 구성할 수 있는 통합 창작 작업 공간이다.

사용자는 정해진 형식에 얽매이지 않고 문서와 컴포넌트를 조합하여 자신만의 작업 환경을 만들 수 있다.

캐릭터와 세계관을 정리하고, 게임을 기획하고, 자료를 수집하고, 시각적으로 연결하고, 프로젝트 전체를 관리하는 모든 과정을 하나의 환경에서 수행할 수 있도록 한다.
