# BLANKSPACE — UI 인터랙션·애니메이션 기획서

> 이 문서는 사용자가 UI를 **클릭하거나 드래그했을 때** 어떤 애니메이션으로 어떤 기능이 나오는지를 정리한다.
> 화면별 기능과 구조는 「Blankspace_UI_작동원리_기획서.md」를 기준으로 한다.

## 표기 규칙

| 표기 | 의미 |
|---|---|
| **[확정]** | 사용자가 정한 **기능** (무엇이 일어나는가) |
| **[제안]** | 시안 작성 중 제안했고 아직 확정 전인 기능 |
| **[미정]** | 추가 결정 필요 |

> **중요**: 이 문서의 **시간(ms), 곡선, 거리 같은 애니메이션 수치는 모두 [제안]**이다. 지금까지 확정한 것은 기능이며, 모션 수치는 아직 정한 적이 없다. 시안은 정지 화면이라 실제 움직임은 프로토타입으로 확인해야 한다.

## 1. 모션 시스템 (공통 기준) [제안]

### 1-1. 시간 기준

| 이름 | 시간 | 주로 쓰는 곳 |
|---|---|---|
| instant | 0ms | 드래그 중 포인터 추적, 입력 반영 |
| fast | 120ms | 호버, 눌림, 툴팁, 아이콘 전환 |
| base | 200ms | 모달·팝오버 열기, 패널 전환, 접기/펼치기, 목록 재배치 |
| slow | 320ms | 화면 전환, 확대 전환, 줌, 노드 재배치 |
| draw | 400ms | 선이 그려지는 연출(관계선·연결선·곡선) |

- 닫힘·사라짐은 열림·나타남의 **약 70% 시간**으로 더 빠르게 처리한다.
- 같은 동작은 화면이 달라도 **같은 시간과 곡선**을 쓴다.

### 1-2. 곡선(easing)

| 용도 | 곡선 |
|---|---|
| 나타남 / 이동 | `cubic-bezier(0.2, 0, 0, 1)` (빠르게 시작해 부드럽게 멈춤) |
| 사라짐 | `cubic-bezier(0.4, 0, 1, 1)` |
| 위치 안착(드롭) | `cubic-bezier(0.2, 0, 0, 1)`, 되튐 없음 |
| 진행 막대(오디오 등) | linear |

### 1-3. 애니메이션 대상 속성

- 기본은 **transform(이동·확대)과 opacity(투명도)**만 애니메이션한다.
- 높이가 변하는 접기/펼치기는 grid-rows 방식 등으로 부드럽게 처리한다.
- 색 전환(테마, 호버)은 background-color, border-color, color만 허용한다.
- 한 번에 많은 요소를 동시에 움직이지 않는다(목록 재배치는 FLIP 방식으로 한 번에 계산).

### 1-4. 입력 기준

| 입력 | 기준 |
|---|---|
| 클릭 | 마우스 왼쪽 클릭 / 터치 탭 |
| **길게 누르기** | **500ms** 이상 누름 [확정: 길게 누르면 드래그 상태. 500ms는 제안] |
| 드래그 시작(편집 캔버스) | 6px 이상 이동 |
| 호버 | 마우스 전용. 터치에는 호버 상태 없음 |
| 키보드 | 아래 9번 참고 |

### 1-5. 모션 줄이기 설정 [제안]

시스템의 "동작 줄이기"가 켜져 있으면:
- 이동·확대·슬라이드는 없애고 **투명도 전환(100ms)**만 사용
- 선 그려지기, 흐르는 효과, 타이핑 효과, 깜빡임, 펄스는 끔
- 기능은 그대로 동작한다

## 2. 공통 인터랙션 패턴

### 2-1. 버튼·카드 기본 상태 [제안]

| 상태 | 애니메이션 |
|---|---|
| 호버 | 배경 또는 테두리 색 전환 120ms. 카드는 위로 2px 올라오며 그림자 약간 강해짐 |
| 눌림 | scale 0.98, 80ms |
| 포커스(키보드) | 2px 라벤더 링, 즉시 표시 |
| 비활성 | 투명도 0.4, 호버·눌림 효과 없음 |
| 선택됨 | 라벤더 테두리 2px, 배경 연한 라벤더, 120ms 전환 |

### 2-2. 카드 길게 눌러 드래그 정렬 [확정: 직접 정렬이 기본, 길게 누르면 드래그]

대상: 프로젝트 카드, 폴더 카드, 문서 카드, 사운드 카드, 용어·아이템 카드 등 모든 카드형 목록.

| 단계 | 사용자 동작 | 애니메이션 | 결과·기능 |
|---|---|---|---|
| 1 | 카드를 누르고 있음 (0~500ms) | 카드가 눌림 상태(scale 0.98)로 유지 | 아직 클릭도 드래그도 아님. 중간에 손을 떼면 일반 클릭 |
| 2 | 500ms 경과 | **들어올림**: scale 1.04, 그림자 확대, 투명도 0.95, 200ms. 원래 자리에는 **점선 자리 표시**가 페이드 인 | **드래그 상태** 진입 |
| 3 | 포인터를 움직임 | 카드가 포인터를 **지연 없이** 따라감(0ms). 다른 카드는 가만히 있음 | 이동 중 |
| 4 | 다른 카드 영역 위로 진입 | 자리 표시가 새 위치로 이동하고, 영향받은 카드들이 **200ms 동안 밀려 이동**(FLIP) | 순서 미리보기 |
| 5 | 화면 가장자리 48px 안으로 이동 | 스크롤이 자동으로 진행(가장자리에 가까울수록 빠름) | 긴 목록 정렬 |
| 6 | 손을 뗌(놓기) | 카드가 자리 표시 위치로 **180ms 안착**하고 그림자 제거 | 순서 저장, 저장 상태 "저장 중 → 저장됨" |
| 취소 | ESC 또는 허용되지 않은 영역에 놓음 | 카드가 원래 자리로 200ms 복귀 | 변경 없음 |

**폴더로 문서 이동** [제안]
- 문서 카드를 폴더 카드의 **가운데 영역**에 올리면 폴더 카드가 라벤더 테두리로 강조되고 scale 1.03(120ms) → 놓으면 문서 카드가 폴더 쪽으로 **축소되며 사라짐**(scale 0.3, 투명도 0, 240ms) + 토스트 "○○ 폴더로 이동했습니다 · 실행 취소"
- 폴더 카드의 **가장자리 영역**에 놓으면 순서 변경으로 처리
- **같은 프로젝트 안에서만 이동 가능** [확정]. 다른 프로젝트(사이드바 트리)로 끌면 금지 커서와 함께 카드가 좌우로 짧게 흔들림(120ms) + 토스트로 사유 안내
- 이동해도 문서 ID와 내부 링크는 유지 [확정, 기획서 3-3]

**키보드 대체** [제안]: 카드 선택 후 메뉴의 "위치 바꾸기" 또는 Alt+방향키로 이동.

### 2-3. 모달 [확정: 바깥 빈 곳 클릭 시 닫힘]

| 동작 | 애니메이션 | 결과 |
|---|---|---|
| 열기 | 배경 어둡게 페이드(0→0.45, 200ms) + 모달 scale 0.96→1, 투명도 0→1 (200ms) | 모달 표시, 포커스가 모달 안으로 이동, 뒤 화면 스크롤 잠김 |
| 닫기 | 모달 투명도 1→0, scale 1→0.98 (140ms) + 배경 페이드 아웃 | 포커스가 원래 위치로 복귀 |
| 닫는 방법 | **바깥 빈 곳 클릭 [확정]**, × 버튼, ESC | 입력 중인 내용이 있으면 닫기 전에 확인 [제안] |
| 모달 위 모달 | 위의 모달만 열림, 아래 모달은 한 단계 더 어두워짐 | 영구 삭제 확인 등 |

### 2-4. 카드에서 모달로 확대 (용어·아이템 카드) [확정: 눌렀을 때 모달처럼 확대]

| 단계 | 애니메이션 |
|---|---|
| 클릭 | 눌린 카드가 있던 **위치와 크기에서 모달 크기로 확대**(280ms). 배경은 동시에 어두워짐 |
| 내용 | 확대가 끝나갈 때 모달 내부 내용이 페이드 인(120ms, 100ms 지연) |
| 닫기 | 역방향으로 카드 자리로 축소(220ms) |
| 결과 | 용어: 전체 설명, 분류, 관련 문서 / 아이템: 등급, 효과, 가격, 획득처, 설명, 관련 문서 |

### 2-5. 토스트 [확정: 팝업은 토스트]

| 항목 | 내용 [제안] |
|---|---|
| 위치 | 화면 아래 가운데 |
| 나타남 | 아래에서 16px 올라오며 페이드 인, 200ms |
| 유지 | 4초 (실행 취소 버튼이 있으면 6초). 마우스를 올리면 타이머 정지 |
| 사라짐 | 아래로 8px 내려가며 페이드 아웃, 140ms |
| 여러 개 | 최대 3개 쌓임. 새 토스트가 들어오면 기존 것이 위로 밀림(200ms) |
| 종류 | 성공(기본), 오류(빨간 강조), 실행 취소 가능 |

### 2-6. 저장 상태 표시 [확정: 글씨와 색으로 표시]

|---|---|---|

| 저장 실패 | 빨강 "저장 실패" + 다시 시도 | 크로스페이드 + 오류 토스트 |

## 3. 공간 화면별 인터랙션

### 3-1. 메인 (화면 1)

| 동작 | 애니메이션 [제안] | 결과 |
|---|---|---|
| 프로젝트 카드 호버 | 위로 2px, 그림자 강화, 120ms | |
| 프로젝트 카드 클릭 | 카드 커버가 프로젝트 화면의 상단 배너 크기로 확대되는 전환(320ms) | 프로젝트 화면 이동 |
| 카드 길게 누르기 | 2-2 참고 | 프로젝트 순서 직접 정렬 [확정] |
| 카드/목록 전환 | 선택 표시 슬라이드 + 카드들이 새 배치로 **재배치 애니메이션**(280ms) | 보기 방식 변경 |
| 즐겨찾기 별 토글 | 별이 scale 1→1.3→1, 색이 채워짐(200ms) | 즐겨찾기 등록/해제 |
| 사이드바 "즐겨찾기" 클릭 | 내용 크로스페이드 200ms | 즐겨찾기 목록 표시 [확정: 메인에는 최근 작업만] |
| 새 프로젝트 | 만든 뒤 카드가 목록에 scale 0.9→1로 나타나며 1초간 강조 + 토스트 | 프로젝트 생성 |
| 검색창 포커스 | 입력창이 넓어짐(200ms) | 전체 검색 [확정: 상단 바] |

## 8. 데이터 안전과 인터랙션 [확정: 기획서 11, 14]

- 애니메이션이 끝나기 전에도 **데이터는 즉시 일관된 상태**를 가진다(연출 중에 저장이 꼬이지 않도록).
- 드래그 중에는 저장하지 않고, **놓은 뒤 한 번만** 저장한다.
- 삭제, 이동, 색 대체 등 되돌릴 수 있는 작업은 **실행 취소**를 제공한다.
- 저장 성공 표시는 실제 저장 완료 후에만 한다.
- 보기 모드에서는 편집 UI뿐 아니라 데이터 변경 경로도 막는다.

| Tab / Shift+Tab | 포커스 이동(포커스 링 표시) |
| ← → (모달) | 이전·다음 항목(텍스처 맵 등) |

접근성
- **드래그로 할 수 있는 모든 일은 키보드나 메뉴로도 할 수 있어야 한다**(카드 위치 바꾸기, 컴포넌트 이동 등).
- 모달은 열리면 포커스를 안에 가두고, 닫히면 원래 위치로 되돌린다.
- 색만으로 상태를 구분하지 않는다(저장 상태는 글자와 색을 함께 사용 [확정]).
- 깜빡임은 초당 3회를 넘기지 않는다.

## 10. 구현 시 유의 사항 [제안]

- 모션 시간·곡선은 **한곳에서 정의한 값**을 모든 화면이 사용한다.
- 목록·카드 재배치는 한 번에 위치를 계산해 이동시키는 방식(FLIP)으로 처리한다.
- 컴포넌트가 매우 많은 문서에서는 재배치 애니메이션을 줄이거나 생략한다.
- 드래그 중 화면 갱신은 한 프레임에 한 번만 한다.
- 다크 모드 전환 시에도 같은 전환 시간(300ms)을 사용한다.
- 정지 시안만으로는 모션을 확인할 수 없으므로, 핵심 5개 인터랙션을 프로토타입으로 먼저 검증한다.
  1. 카드 길게 눌러 정렬 (2-2)
  2. 관계도 프로필 클릭 3단계 (6-1)
  3. 지도·UI/UX 마커 팝업 (6-2, 6-3)
  4. 카드 → 모달 확대 (2-4)
  5. 컬러 팔레트 스포이드 (5-3)

## 11. 아직 정해야 할 항목 [미정]

**기능**
- 마커를 삭제했을 때 UI/UX 번호를 다시 정렬할지
- 공식 연결을 끊었을 때 곡선 값을 유지할지, 하나의 공식을 여러 곡선에 연결할 수 있는지
- 게임 플로우 연결선의 규칙(어떤 노드끼리 연결 가능한지)
- 검색 중 간이 결과 창
- 파일 삭제 정책(파일 보관함)
- 문서 이동 시 다른 프로젝트로 보내는 경우의 안내 방식

**모션**
- 길게 누르기 시간(500ms)과 드래그 시작 거리(6px)의 확정값
- 대화 스크립트 미리보기의 타이핑 효과 사용 여부와 속도
- 화면 전환의 방향성 연출(슬라이드)을 쓸지, 모두 크로스페이드로 단순하게 갈지
- 카드 → 모달 확대 전환을 모든 모달에 쓸지, 용어·아이템·텍스처 맵에만 쓸지

**검증**
- 위 5개 핵심 인터랙션의 프로토타입 제작 및 확인
