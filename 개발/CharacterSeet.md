# Blankspace - 캐릭터 시트 템플릿 개선 및 커스터마이징 시스템 통합 개발 지시

## 1. 개발 목표

현재 구현된 Blankspace의 캐릭터 시트 템플릿을 개선하고, 사용자가 자신의 목적에 맞게 자유롭게 구성할 수 있는 커스터마이징 시스템을 완성한다.

이번 작업은 기존 캐릭터 시트를 기반으로 한 개선 작업이다.

새로운 템플릿이나 별도의 편집 시스템을 추가하는 것이 아니라, 현재 구현된 캐릭터 시트의 구조와 기능을 최대한 유지하면서 필요한 기능을 개선하고 확장한다.

캐릭터 시트는 고정된 정보 입력 양식이 아니다.

사용자가 캐릭터의 종류와 창작 목적에 따라 구성 요소를 추가하거나 제거하고, 각 요소의 위치와 크기, 디자인, 내부 항목을 자유롭게 변경할 수 있어야 한다.

예를 들어 판타지 캐릭터, 현대물 캐릭터, 몬스터, NPC 등 서로 다른 종류의 캐릭터를 하나의 캐릭터 시트 템플릿으로 관리할 수 있어야 한다.

**핵심 원칙은 기본 구성을 제공하되, 사용자가 원하는 형태로 자유롭게 변경할 수 있도록 하는 것이다.**

# 2. 기존 구현 분석 및 유지 원칙

작업을 시작하기 전에 현재 캐릭터 시트의 코드와 데이터 구조를 먼저 확인한다.

다음 항목을 분석한다.

- 현재 캐릭터 시트의 전체 UI 구조
- 기존 구성 요소의 종류와 역할
- 카드 내부 데이터 구조
- 카드 위치 및 크기 저장 방식
- 편집 모드와 보기 모드 구현 상태
- 색상 및 테마 적용 방식
- 텍스트 스타일 적용 방식
- 이미지 삽입 및 관리 방식
- 기존 데이터 저장 및 불러오기 방식
- 기존 캐릭터 시트의 커스터마이징 기능

기존에 정상 작동하는 기능을 무작정 삭제하거나 전체 시스템을 새로 작성하지 않는다.

현재 구현된 구조를 최대한 재사용하면서 문제를 수정하고 필요한 기능을 확장한다.

기존 캐릭터 데이터와 설정은 반드시 보존한다.

데이터 구조 변경이 필요하다면 기존 데이터와의 호환성을 확인하고, 마이그레이션 및 백업을 고려한다.

# 3. 보기 모드와 편집 모드

캐릭터 시트는 보기 모드와 편집 모드를 명확하게 구분한다.

기본 상태는 보기 모드로 설정한다.

## 3-1. 보기 모드

보기 모드에서는 캐릭터의 정보를 확인하는 데 집중한다.

가능한 작업:
- 캐릭터 정보 확인
- 카드 내용 읽기
- 이미지 확인
- 섹션 및 카드 내용 확인

불가능한 작업:
- 텍스트 수정
- 카드 위치 변경
- 카드 크기 변경
- 카드 추가 및 삭제
- 카드 내부 항목 추가 및 삭제
- 디자인 변경
- 색상 변경
- 구성 요소의 구조 변경

보기 모드에서는 실제 수정 동작 자체를 차단한다.

편집용 핸들, 입력창, 삭제 버튼 및 편집 전용 컨트롤도 비활성화하거나 숨긴다.

## 3-2. 편집 모드

별도의 `편집` 버튼을 눌러 편집 모드에 진입한다.

편집 모드에서는 다음 작업이 가능하다.

- 캐릭터 데이터 수정
- 구성 요소 추가 및 삭제
- 구성 요소 이동
- 구성 요소 크기 변경
- 구성 요소 복제
- 구성 요소 순서 변경
- 카드 내부 항목 추가 및 삭제
- 카드 내부 항목 이름 및 값 변경
- 카드 내부 항목 순서 변경
- 이미지 추가 및 교체
- 색상 및 디자인 변경
- 템플릿 레이아웃 변경

편집 모드에서는 `완료` 버튼을 제공한다.

완료 버튼을 누르면 보기 모드로 돌아간다.

모드를 전환해도 기존 캐릭터 데이터와 템플릿 설정은 유지되어야 한다.

## 3-3. 캐릭터 데이터 편집과 템플릿 구조 편집 구분

캐릭터 데이터 편집과 템플릿 구조 편집은 구분해야 한다.

예를 들어 다음 두 작업은 서로 다른 작업이다.

- 캐릭터의 이름을 변경하는 작업
- 이름을 입력하는 항목 자체를 추가하거나 삭제하는 작업

전자는 캐릭터 데이터 편집이고 후자는 템플릿 구조 편집이다.

캐릭터 정보를 입력하거나 수정하는 과정에서 실수로 템플릿의 구조가 변경되지 않도록 한다.

구성 요소의 구조나 레이아웃을 변경하는 기능은 별도의 편집 컨트롤을 통해 접근할 수 있도록 설계한다.

# 4. 캐릭터 시트의 기본 구성 요소

캐릭터 시트는 의미 있는 구성 요소 단위로 관리한다.

모든 요소를 개별 텍스트나 선, 도형으로 분해하는 방식은 사용하지 않는다.

예를 들어 정보 카드는 하나의 독립적인 구성 요소로 취급한다.

카드 내부의 항목은 해당 카드의 설정을 통해 관리한다.

기본적으로 다음 구성 요소를 제공한다.

## 4-1. 캐릭터 이미지

캐릭터의 대표 이미지 및 참고 이미지를 표시하는 구성 요소다.

지원할 기능:
- 이미지 삽입 및 교체
- 이미지 삭제
- 이미지 크기 조절
- 이미지 위치 조절
- 이미지 비율 설정
- 이미지 자르기 방식 설정
- 이미지 프레임 디자인 설정
- 이미지 영역 크기 조절

대표 이미지뿐 아니라 전신 이미지, 표정 이미지, 의상 참고 이미지 등 다양한 용도로 사용할 수 있어야 한다.

## 4-2. 이름 요소

캐릭터의 이름 및 기타 주요 명칭을 표시하는 구성 요소다.

이름 요소는 특정 언어나 특정한 두 가지 이름 형식으로 고정하지 않는다.

사용자가 여러 개의 이름 필드를 추가하고 각 필드의 이름과 값을 직접 설정할 수 있어야 한다.

예시:
- 이름 name
- 항목 : 내용
- 항목 : 내용

위 내용은 형식 예시일 뿐 실제 고정된 필드가 아니다.

지원할 기능:
- 이름 필드 추가 및 삭제
- 필드 이름 변경
- 필드 값 변경
- 필드 순서 변경
- 글꼴 변경
- 글자 크기 변경
- 글자 색상 변경
- 정렬 변경

단, 대표 이름을 표시하는 요소에서는 불필요한 항목 라벨을 숨길 수 있어야 한다.

예를 들어 `이름 : 새 캐릭터` 대신 `새 캐릭터`만 표시하는 방식이다.

이 설정은 화면 표시 방식에만 영향을 주며 기존 데이터 구조는 유지한다.

## 4-3. 공통 정보 카드

기본 정보 카드와 표 형식의 상세 정보 카드를 하나의 공통 정보 카드 구성 요소로 통합한다.

사용자가 원하는 정보 항목을 직접 구성할 수 있어야 한다.

지원할 기능:
- 카드 제목 변경
- 항목 추가 및 삭제
- 항목 이름 변경
- 항목 값 변경
- 항목 순서 변경
- 항목별 표시 방식 설정
- 카드 내부 여백 조절
- 항목 간 간격 조절
- 카드 디자인 변경

정보 항목은 특정한 캐릭터 정보에 고정하지 않는다.

사용자가 원하는 이름과 값으로 자유롭게 구성할 수 있어야 한다.

## 4-4. 서술형 상세 정보 카드

캐릭터의 성격, 배경, 외형, 특징 등을 자유롭게 서술하는 구성 요소다.

지원할 기능:
- 카드 제목 변경
- 자유로운 텍스트 입력
- 텍스트 수정
- 텍스트 정렬
- 글꼴 변경
- 글자 크기 변경
- 글자 색상 변경
- 카드 디자인 변경

여러 줄의 긴 텍스트를 입력할 수 있어야 한다.

## 4-5. 카테고리 및 키워드 카드

캐릭터의 특징을 태그 형태로 정리하는 구성 요소다.

기본적으로 `#키워드` 형태의 태그를 사용할 수 있어야 한다.

지원할 기능:
- 태그 추가 및 삭제
- 태그 이름 변경
- 태그 색상 변경
- 태그 순서 변경
- 태그 디자인 변경

태그가 많아지면 자동으로 줄바꿈되어야 한다.

기존 표시 형식 설정은 제거한다.

## 4-6. 능력치 레이더 차트

캐릭터의 능력치를 시각적으로 표현하는 선택형 구성 요소다.

지원할 기능:
- 축 개수 변경
- 축 이름 변경
- 축별 수치 설정
- 최대 수치 설정
- 차트 크기 조절
- 차트 색상 변경
- 차트 디자인 변경

5축, 6축, 8축 등 다양한 축 개수를 지원한다.

레이더 차트는 선택형 구성 요소이며 필수로 사용하지 않아도 된다.

능력치를 텍스트로 작성하고 싶은 사용자는 공통 정보 카드로 대체할 수 있어야 한다.

## 4-7. 관계 요약 카드

캐릭터의 주요 관계를 간단히 기록하는 구성 요소다.

지원할 기능:
- 관계 대상 이름
- 관계 내용
- 관계 상태
- 관계 상태별 색상 변경

복잡한 관계도나 노드 편집 기능은 포함하지 않는다.

관계도는 별도의 관계도 템플릿에서 관리한다.

## 4-8. 대표 대사 카드

캐릭터를 대표하는 대사나 말투를 기록하는 구성 요소다.

지원할 기능:
- 카드 제목 변경
- 대사 입력 및 수정
- 글자 색상 변경
- 글꼴 및 글자 크기 변경
- 텍스트 정렬
- 카드 디자인 변경

대사 분기나 전체 대화 시스템은 포함하지 않는다.

## 4-9. 자유 메모 카드

사용자가 원하는 내용을 자유롭게 기록하는 일반 메모 구성 요소다.

지원할 기능:
- 카드 제목 변경
- 텍스트 입력 및 수정
- 글자 색상 변경
- 배경색 변경
- 테두리 색상 변경
- 카드 디자인 변경

# 5. 구성 요소 커스터마이징

캐릭터 시트의 핵심 기능이다.

사용자는 기본 구성 요소를 그대로 사용할 수도 있고, 필요한 구성 요소를 추가하거나 삭제할 수도 있어야 한다.

## 5-1. 구성 요소 관리

다음 기능을 제공한다.

- 구성 요소 추가
- 구성 요소 삭제
- 구성 요소 복제
- 구성 요소 선택
- 구성 요소 이동
- 구성 요소 크기 조절
- 구성 요소 앞뒤 배치 순서 변경
- 구성 요소 정렬
- 구성 요소 간 간격 조절

구성 요소는 의미 있는 단위로 유지한다.

카드 내부의 장식용 선이나 개별 글자를 별도의 독립 오브젝트로 분해하지 않는다.

## 5-2. 카드 내부 항목 관리

정보 카드 등 내부 항목이 존재하는 구성 요소는 내부 항목을 자유롭게 관리할 수 있어야 한다.

- 항목 추가
- 항목 삭제
- 항목 이름 변경
- 항목 값 변경
- 항목 순서 변경
- 항목 이동
- 입력 형식 변경

카드 자체의 구조와 내부 항목의 구조를 구분한다.

## 5-3. 입력 형식 커스터마이징

사용자가 새로운 항목을 추가할 때 입력 형식을 선택할 수 있도록 한다.

기본적으로 다음 형식을 고려한다.

- 한 줄 텍스트
- 여러 줄 텍스트
- 숫자
- 날짜
- 드롭다운 선택
- 체크박스
- 이미지
- 이미지 갤러리
- 링크

항목 이름과 입력 형식은 독립적으로 변경할 수 있어야 한다.

예를 들어 `마법 속성`이라는 항목을 만들고 입력 형식을 드롭다운으로 설정할 수 있어야 한다.

`캐릭터 배경 이야기`라는 항목은 여러 줄 텍스트 형식으로 설정할 수 있어야 한다.

# 6. 구성 요소 배치 및 크기 조절

사용자는 캐릭터 시트의 전체 레이아웃을 직접 변경할 수 있어야 한다.

지원할 기능:
- 구성 요소 드래그 이동
- 구성 요소 크기 조절
- 구성 요소 복제
- 구성 요소 정렬
- 구성 요소 앞뒤 순서 변경
- 구성 요소 간 간격 조절

드래그 가능한 요소는 편집 모드에서 자연스럽게 이동해야 한다.

텍스트 입력이나 버튼 조작이 드래그와 충돌하지 않도록 한다.

구성 요소를 이동하거나 크기를 조절한 후 저장 및 새로고침을 하더라도 위치와 크기가 유지되어야 한다.

## 6-1. 카드별 크기 조절 규칙

카드의 크기 조절은 카드의 특성에 맞춰 처리한다.

### 공통 정보 카드
- 가로 크기: 사용자 조절 가능
- 세로 크기: 내부 내용에 따라 자동 조절
- 내부 스크롤: 사용하지 않음
- 텍스트 줄바꿈 지원

### 서술형 상세 카드
- 가로 크기: 사용자 조절 가능
- 세로 크기: 텍스트 길이에 따라 자동 조절
- 내부 스크롤: 사용하지 않음
- 텍스트 줄바꿈 지원

### 키워드 및 태그 카드
- 가로 크기: 사용자 조절 가능
- 세로 크기: 태그 개수에 따라 자동 조절
- 내부 스크롤: 사용하지 않음
- 태그 자동 줄바꿈 지원

### 관계 요약 카드
- 가로 크기: 사용자 조절 가능
- 세로 크기: 관계 정보에 따라 자동 조절
- 내부 스크롤: 사용하지 않음

### 기타 구성 요소
각 요소의 목적에 맞게 크기 조절 방식을 결정한다.

모든 카드에 동일한 크기 조절 방식을 무조건 적용하지 않는다.

## 6-2. 텍스트 오버플로 방지

텍스트가 카드 영역을 벗어나거나 다른 요소와 겹치는 문제를 방지한다.

- 자동 줄바꿈
- 내용에 따른 카드 높이 조절
- 카드 내부 여백 유지
- 긴 텍스트에 대한 적절한 표시
- 구성 요소 간 겹침 방지

내용이 늘어나면 카드의 높이가 자동으로 증가해야 한다.

사용자가 세로 크기를 직접 조절할 수 없는 카드에서는 높이를 자동으로 계산한다.

구성 요소의 종류에 따라 우측 패널에 표시되는 항목이 달라져야 한다.

- 항목별 입력 형식 설정
- 항목 삭제 버튼
- 항목 추가 버튼
- 항목 순서 변경 기능
- 카드 디자인 설정

## 7-2. 이름 요소 선택 시

- 이름 필드 목록
- 필드 이름 및 값 설정
- 필드 추가 및 삭제

## 7-3. 이미지 선택 시

## 7-4. 텍스트 및 메모 카드 선택 시

- 전체 배경색
- 전체 레이아웃

- 기본 색상
- 전체 간격
- 기타 템플릿 디자인 설정

우측 편집 패널은 현재 선택한 요소를 편집하는 공간이라는 점을 명확하게 유지한다.

# 8. 색상 및 디자인 커스터마이징

캐릭터 시트의 디자인을 사용자가 자유롭게 변경할 수 있어야 한다.

## 8-1. 색상 설정

- 기본 색상 팔레트
- 사용자 지정 색상
- 카드 배경색
- 테두리 색상
- 테두리 두께
- 글자 색상
- 이름 요소 색상
- 관계 상태별 색상
- 자유 메모 카드 색상

글자 색상은 실제 텍스트에 적용되어야 한다.

모든 구성 요소에서 동일한 방식으로 색상 변경이 정상적으로 작동해야 한다.

변경한 색상은 저장 후 다시 불러와도 유지되어야 한다.

테마 색상과 개별 요소 색상이 충돌하지 않도록 한다.

특정 색상이 코드에 고정되어 테마 변경을 방해하는 문제가 없도록 확인한다.

## 8-2. 배경 디자인

다음 디자인을 고려한다.

- 단색 배경
- 그라데이션
- 간단한 패턴 배경

그라데이션은 색상과 방향을 설정할 수 있어야 한다.

패턴은 점무늬, 줄무늬 등 미리 제공되는 간단한 패턴을 선택하는 방식으로 구성한다.

패턴의 색상, 간격, 크기 등을 변경할 수 있도록 한다.

복잡한 일러스트레이터 수준의 패턴 제작 기능은 구현하지 않는다.

## 8-3. 기타 디자인

- 글꼴
- 글자 크기
- 텍스트 정렬
- 카드 모양
- 테두리
- 여백
- 간격
- 이미지 프레임

# 9. 사용자 정의 캐릭터 시트 템플릿 저장

사용자가 직접 구성한 캐릭터 시트의 구조를 개인 템플릿으로 저장하고 재사용할 수 있어야 한다.

이 기능은 단순히 색상이나 외형을 저장하는 디자인 프리셋과 구분한다.

디자인 프리셋은 시각적인 설정을 저장한다.

사용자 정의 캐릭터 시트 템플릿은 구성 요소와 정보 구조까지 저장한다.

## 9-1. 저장할 정보

- 전체 레이아웃
- 구성 요소의 종류
- 구성 요소의 위치와 크기
- 구성 요소 내부 항목의 구조
- 항목 이름
- 항목 입력 형식
- 구성 요소의 순서
- 색상 및 디자인 설정
- 글꼴 및 텍스트 스타일
- 기타 템플릿 구조 설정

## 9-2. 템플릿 관리 기능

- 사용자 정의 템플릿 저장
- 템플릿 이름 변경
- 템플릿 복제
- 템플릿 삭제
- 저장된 템플릿 불러오기
- 기본 캐릭터 시트로 복원

## 9-3. 캐릭터 데이터와 템플릿 구조 분리

가장 중요한 사항이다.

템플릿의 구조와 개별 캐릭터의 실제 데이터는 분리해서 저장한다.

예를 들어 사용자가 특정 캐릭터의 이름과 정보를 입력한 상태에서 템플릿을 저장하더라도, 다른 캐릭터를 생성할 때는 새로운 데이터를 입력할 수 있어야 한다.

사용자 정의 템플릿을 적용할 때 기존 캐릭터의 데이터가 임의로 복사되거나 덮어쓰여서는 안 된다.

새 캐릭터 생성 시 저장된 템플릿의 구조만 가져오고 실제 캐릭터 정보는 새로운 상태로 시작해야 한다.

기존 캐릭터에 템플릿을 적용할 때는 데이터 손실이 발생하지 않도록 적용 방식을 구분하고 확인 절차를 제공한다.

# 10. 자유 메모 카드 및 색상 테마 수정

자유 메모 카드에서 테마 색상을 변경했을 때 다음 요소에도 정상적으로 반영되어야 한다.

- 카드 테두리
- 카드 제목
- 카드 장식 요소
- 배경색
- 글자 색상

특정 색상이 코드에 고정되어 테마 변경을 방해하지 않도록 수정한다.

테마 변경 이후에도 저장 및 불러오기가 정상적으로 작동해야 한다.

모든 커스터마이징 설정과 캐릭터 데이터는 정상적으로 저장되어야 한다.

저장해야 하는 정보는 다음과 같다.

### 캐릭터 데이터
- 캐릭터 이름 및 정보
- 카드 내부 내용
- 텍스트
- 이미지 참조
- 기타 캐릭터별 정보

### 템플릿 구조
- 구성 요소 종류
- 구성 요소 위치
- 구성 요소 크기
- 구성 요소 순서
- 카드 내부 항목 구조
- 항목별 입력 형식

### 디자인 설정
- 색상
- 글꼴
- 글자 크기
- 배경
- 테두리
- 간격
- 기타 디자인 설정

저장 시스템은 Blankspace의 공통 저장 기준을 따른다.

연속 저장 과정에서 이전 데이터가 최신 데이터를 덮어쓰지 않도록 한다.

저장 성공 여부를 실제 결과에 따라 표시한다.

새로고침 후에도 모든 데이터와 커스터마이징 설정이 유지되어야 한다.

기존에 저장된 캐릭터 데이터가 손상되거나 삭제되지 않도록 한다.

이번 작업은 기존 캐릭터 시트 개선 작업이지만, Blankspace의 UI 우선 개발 원칙을 그대로 적용한다.

## 1단계: 기존 UI 분석

현재 캐릭터 시트의 화면과 기능을 확인한다.

## 2단계: UI 개선

다음 UI를 먼저 구현한다.

- 보기 모드 및 편집 모드
- 기본 캐릭터 시트 화면
- 구성 요소 추가 UI

- 레이아웃 편집 UI

완성된 UI를 사용자에게 보여준다.

수정 요청이 있다면 UI를 먼저 수정한다.

사용자의 승인을 받기 전까지 실제 기능 구현으로 넘어가지 않는다.

## 4단계: 기능 구현

승인된 UI를 기준으로 실제 기능을 구현한다.

단순히 버튼이나 메뉴만 추가하지 말고 실제 동작을 연결한다.

## 5단계: 테스트

실제 브라우저에서 모든 기능을 테스트한다.

## 6단계: 도움말 업데이트

# 15. 작업 시 주의사항

1. 기존 캐릭터 시트의 기능을 무작정 삭제하지 않는다.
2. 현재 데이터 구조를 최대한 유지한다.
3. 기존에 저장된 캐릭터 데이터가 손상되지 않도록 한다.
4. 의미 있는 구성 요소 단위의 편집 방식을 유지한다.
5. 개별 텍스트나 장식용 선까지 모든 요소를 원시적인 오브젝트로 분해하지 않는다.
6. 캐릭터 데이터 편집과 템플릿 구조 편집을 구분한다.
7. 디자인 프리셋과 사용자 정의 템플릿 저장 기능을 구분한다.
8. 보기 모드에서는 실제 수정 동작을 차단한다.
9. 드래그 가능한 요소는 정상적으로 이동할 수 있어야 한다.
10. 텍스트 입력과 드래그가 충돌하지 않도록 한다.
11. 기존 공통 저장 시스템과 충돌하지 않도록 한다.
12. 사용자가 요청하지 않은 기능을 임의로 추가하지 않는다.
13. 테스트하지 않은 기능을 정상 작동한다고 보고하지 않는다.
