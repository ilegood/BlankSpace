# 1. 프로젝트의 기본 목표

현재 Blankspace의 전체적인 사이트 UI와 공통 레이아웃은 유지한다.

기존 템플릿 구현은 코드를 먼저 분석한 후, 필요한 경우 기존 템플릿 구현을 정리하고 새롭게 재구축한다.

단, 템플릿 구현을 삭제하거나 재구축하는 과정에서 기존 사용자의 문서와 데이터가 손실되어서는 안 된다.

이번 작업의 핵심 목표는 다음과 같다.

1. 기존 사이트의 공통 UI와 전체적인 디자인 유지
2. 템플릿 시스템 전반의 재구축
3. 템플릿별 목적에 맞는 UI와 기능 설계
4. 모든 템플릿에 공통 편집 모드 규칙 적용
5. 다크 모드 완벽 지원
6. 디자인 프리셋 시스템 구축
7. 도움말 시스템 구축 및 기능별 설명 제공
8. 기존 사용자 데이터 보존

**가장 중요한 원칙은 UI를 먼저 완성하고, 사용자의 확인을 받은 뒤 기능을 구현하는 것이다.**

UI와 기능을 한꺼번에 구현하지 않는다.

# 2. 개발 시작 전 기존 코드 분석

개발에 착수하기 전에 현재 프로젝트의 구조와 코드를 먼저 분석한다.

다음 항목을 확인한다.

- 프로젝트의 전체 폴더 및 파일 구조
- 기존 템플릿의 구현 방식
- 공통 UI 및 레이아웃 구조
- 문서 저장 및 불러오기 방식
- 사용자 데이터 저장 방식
- 이미지 및 파일 관리 방식
- 문서 간 연결 관계 및 참조 데이터
- 편집 모드와 보기 모드의 기존 구현
- 다크 모드 구현 상태
- 기존 디자인 프리셋 및 설정 저장 방식
- 기존 도움말 시스템
- 템플릿별 공통 컴포넌트와 개별 컴포넌트

분석이 끝나면 다음 내용을 보고한다.

1. 현재 구현된 기능
2. 정상 작동하는 기능
3. 문제가 있는 기능
4. 재사용할 수 있는 공통 컴포넌트
5. 재구축해야 하는 템플릿 구현
6. 기존 데이터와의 호환성 및 보존 방법
7. 작업 중 주의해야 할 사항

기존 코드를 충분히 분석하기 전에는 임의로 삭제하거나 수정하지 않는다.

## 기존 구현 삭제 및 재구축 원칙

기존 템플릿의 UI와 내부 구현을 재구축할 수 있다.

단, 다음 항목은 삭제하거나 임의로 초기화하지 않는다.

- 기존 사용자의 문서
- 문서 내용
- 문서 ID
- 이미지 및 파일
- 문서 간 연결 관계
- 저장된 디자인 설정
- 사용자 설정
- 기존 데이터베이스 정보

즉, 삭제 대상은 템플릿의 기존 구현 코드이지 사용자의 실제 데이터가 아니다.

데이터 구조 변경이나 마이그레이션이 필요하다면 사전에 설명하고 승인을 받는다.

# 3. 개발 진행 방식: UI 우선

모든 템플릿은 다음 순서로 개발한다.

### 1단계: UI 설계

- 템플릿의 전체적인 레이아웃 구성
- 요소 배치
- 버튼 및 메뉴 구성
- 정보 표시 방식
- 편집 모드와 보기 모드의 화면 구성
- 다크 모드 화면 구성

이 단계에서는 실제 데이터 처리 기능을 구현하지 않는다.

UI 확인을 위한 정적 화면이나 임시 데이터는 사용할 수 있다.

### 2단계: UI 확인 및 승인

사용자가 실제 화면을 확인한다.

수정 요청이 있다면 UI를 먼저 수정한다.

사용자가 UI를 승인하기 전에는 다음 단계로 넘어가지 않는다.

### 3단계: 기능 구현

승인된 UI를 기준으로 기능을 연결한다.

- 데이터 추가 및 수정
- 삭제
- 저장 및 불러오기
- 드래그 및 배치
- 요소 간 연결
- 검색 및 필터
- 기타 템플릿별 기능

### 4단계: 테스트

구현한 기능을 직접 테스트한다.

### 5단계: 도움말 업데이트

새롭게 추가하거나 수정한 기능을 도움말에 반영한다.

### 6단계: 다음 템플릿 진행

현재 템플릿의 테스트와 승인이 완료된 후 다음 템플릿으로 넘어간다.

**절대로 여러 템플릿을 동시에 개발하지 않는다.**

# 4. 모든 템플릿의 공통 편집 규칙

## 4-1. 편집 모드와 보기 모드

모든 템플릿은 반드시 편집 모드와 보기 모드를 구분해야 한다.

이 규칙은 특정 템플릿에만 적용되는 것이 아니라 Blankspace의 모든 템플릿에 공통으로 적용한다.

### 보기 모드

기본적으로 템플릿을 열었을 때는 보기 모드로 표시한다.

보기 모드에서는 다음과 같은 수정 작업을 할 수 없다.

- 텍스트 내용 수정
- 요소 추가 및 삭제
- 요소 드래그 및 이동
- 크기 조절
- 회전
- 요소 연결 및 해제
- 이미지나 파일 교체
- 기타 문서 내용 변경 작업

단순히 버튼만 비활성화하는 것이 아니라 실제 입력, 드래그, 삭제 등 수정 동작 자체가 발생하지 않도록 구현한다.

단, 템플릿의 내용을 확인하기 위한 스크롤, 확대 및 축소, 링크 열기, 미디어 재생 등 읽기 목적의 기능은 템플릿의 특성에 따라 사용할 수 있다.

### 편집 모드

사용자가 편집 모드에 진입했을 때만 수정 기능을 활성화한다.

편집 모드에서는 템플릿에서 허용하는 다음 작업을 수행할 수 있다.

- 텍스트 작성 및 수정
- 요소 추가 및 삭제
- 요소 드래그 및 이동
- 크기 조절
- 회전
- 연결 및 해제
- 이미지 및 파일 관리
- 기타 템플릿별 편집 기능

단, 모든 요소가 무조건 드래그 가능한 것은 아니다.

각 템플릿을 설계할 때 사용자가 지정한 요소별 편집 규칙을 따른다.

### 편집 모드 종료

편집 모드를 종료하면 다시 보기 모드로 전환한다.

- 수정 기능 비활성화
- 드래그 기능 비활성화
- 편집용 핸들 및 컨트롤 숨김
- 편집 UI 정리
- 변경 사항 저장 상태 확인

저장되지 않은 변경 사항이 있다면 임의로 버리지 말고 저장 여부를 처리한다.

## 4-2. 드래그 및 요소 조작 규칙

드래그가 허용된 요소는 편집 모드에서 자연스럽게 이동해야 한다.

사용자가 요소를 클릭하고 드래그하면 해당 요소가 마우스 움직임에 맞춰 이동해야 한다.

다음 사항을 반드시 확인한다.

- 클릭한 요소만 이동하는가?
- 드래그 시작과 종료가 정상 작동하는가?
- 요소가 마우스를 자연스럽게 따라오는가?
- 다른 요소가 의도치 않게 함께 이동하지 않는가?
- 드래그 후 위치가 저장되는가?
- 새로고침 후에도 위치가 유지되는가?
- 텍스트 입력 및 버튼 클릭과 드래그가 충돌하지 않는가?
- 확대 및 축소 상태에서도 정상 작동하는가?
- 스크롤과 드래그가 충돌하지 않는가?

사용자가 특정 요소를 드래그할 수 없다고 명시했다면 해당 요소는 고정한다.

반대로 드래그가 허용된 요소를 임의로 고정하지 않는다.

각 템플릿을 설계할 때 요소별로 다음 항목을 구분한다.

- 드래그 가능 여부
- 크기 조절 가능 여부
- 회전 가능 여부
- 삭제 가능 여부
- 연결 가능 여부
- 내용 편집 가능 여부

사용자가 아직 결정하지 않은 사항은 임의로 확정하지 말고 질문한다.

# 5. 공통 UI 및 레이아웃 규칙

기존 Blankspace의 전체적인 UI와 디자인 방향을 유지한다.

템플릿마다 목적이 다르므로 모든 템플릿을 동일한 카드형 레이아웃으로 만들지 않는다.

각 템플릿의 목적에 적합한 화면 구성을 사용한다.

예를 들어 다음과 같이 구분할 수 있다.

- 문서형: 일반적인 문서 편집기 형태
- 자유 캔버스형: 자유로운 위치에 요소를 배치하는 형태
- 관계도형: 노드와 연결선을 활용하는 형태
- 지도형: 지도와 구역 및 마커를 중심으로 구성하는 형태
- 시간순 정리형: 시간과 사건을 중심으로 구성하는 형태
- 자료 관리형: 파일과 자료를 정리하는 형태

위 내용은 화면 유형을 구분하기 위한 기준이며, 실제 세부 UI는 템플릿별로 사용자와 논의한 후 확정한다.

## 공통 UI 원칙

- 기존 사이트의 전체적인 디자인을 유지한다.
- 기존 공통 메뉴와 내비게이션을 유지한다.
- 템플릿별 UI는 목적에 맞게 설계한다.
- 버튼과 메뉴의 위치 및 역할을 명확하게 구분한다.
- 사용자가 기능을 쉽게 이해할 수 있도록 구성한다.
- 불필요한 UI를 추가하지 않는다.
- 사용자가 요청하지 않은 기능을 임의로 추가하지 않는다.

# 6. 미구현 기능 표시 규칙

아직 구현되지 않은 기능을 마치 정상적으로 작동하는 것처럼 보여서는 안 된다.

미구현 상태인 버튼이나 기능은 사용자가 알아볼 수 있도록 시각적으로 구분한다.

예시:

- 준비 중
- 미구현
- 개발 예정

미구현 버튼은 빨간색 등 눈에 띄는 색상으로 표시한다.

단, 정상적인 조건부 비활성화와 미구현 상태를 혼동해서는 안 된다.

예를 들어 권한이 없거나 필요한 조건을 충족하지 못해서 비활성화된 기능은 별도로 표시한다.

미구현 기능은 실제 구현이 완료되기 전까지 작동하는 것처럼 처리하지 않는다.

# 7. 도움말 시스템

Blankspace에는 사용자가 기능을 이해할 수 있는 도움말 시스템이 필요하다.

모든 템플릿에는 해당 템플릿의 사용 목적과 주요 기능을 설명하는 도움말이 있어야 한다.

새로운 기능이 추가되거나 기존 기능이 변경되면 도움말도 함께 수정한다.

도움말에는 다음 내용을 포함할 수 있다.

- 템플릿의 사용 목적
- 기본적인 사용 방법
- 편집 모드 사용 방법
- 요소 추가 및 삭제 방법
- 드래그 및 배치 방법
- 저장 및 불러오기 방식
- 특수 기능의 사용 방법
- 주의 사항

실제로 구현되지 않은 기능을 도움말에 구현된 것처럼 설명하지 않는다.

# 8. 디자인 프리셋 시스템

디자인 프리셋은 템플릿의 시각적 디자인을 저장하고 재사용하기 위한 기능이다.

템플릿의 데이터 구조나 문서 내용을 저장하는 기능이 아니다.

## 저장 가능한 항목

템플릿의 특성에 따라 다음 항목을 저장할 수 있다.

- 레이아웃
- 카드 배치
- 카드 크기
- 간격
- 색상
- 테두리
- 글꼴 및 글자 스타일
- 이미지 표시 영역
- 시각적 배치 설정
- 기타 템플릿별 디자인 설정

단, 실제 적용 항목은 각 템플릿의 UI 설계 단계에서 결정한다.

## 저장하면 안 되는 항목

- 문서 내용
- 캐릭터 정보
- 세계관 데이터
- 아이템 능력치
- 관계도 데이터
- 이미지 원본 파일
- 문서 ID
- 문서 간 연결 관계
- 템플릿의 기능 및 데이터 구조

## 프리셋 관리 기능

- 프리셋 저장
- 프리셋 이름 변경
- 프리셋 복제
- 프리셋 삭제
- 프리셋 적용
- 기본 디자인으로 복원

프리셋은 새로고침 이후에도 유지되어야 한다.

동일한 템플릿 종류에서만 프리셋을 적용할 수 있다.

다른 템플릿 종류의 프리셋을 임의로 적용하지 않는다.

| 파일 보관함 | 미적용 |

미정 항목은 사용자가 결정하기 전까지 임의로 적용하지 않는다.

# 9. 최종 템플릿 목록 및 목적

아래 목록을 Blankspace의 최종 템플릿 구성 기준으로 사용한다.

## 1. 캐릭터

### 캐릭터 시트

캐릭터의 기본 인적사항, 스토리 및 디자인 등을 정리한다.

### 관계도

캐릭터 간의 관계를 한눈에 보기 쉽게 정리한다.

### 캐릭터 문답

특정 질문이나 상황을 제시했을 때 캐릭터가 어떤 식으로 답하는지 가상의 Q&A 형식으로 정리한다.

캐릭터의 성격과 말투, 반응을 파악하기 위한 자료이다.

## 2. 세계관

### 세계관 시트

세계관의 상세 정보와 분위기 등을 정리한다.

### 지도

세계관의 전체적인 형태와 구역, 세력 등을 정리한다.

### 연대기

세계관의 깊이를 더하고 각 사건의 연대기를 정리한다.

### 용어

세계관의 고유명사 및 자주 사용되는 단어를 정리한다.

## 3. 게임

### 게임 기획

게임의 장르와 콘셉트 등을 정리한다.

### 플로우

게임의 전체적인 진행 방향을 정리한다.

### UI/UX

게임의 UI 설명과 세부 기능, UX 등을 정리한다.

### 아이템

게임 내 아이템의 능력치 및 각종 설명을 정리한다.

### 대사 스크립트

게임 내에서 사용되는 대사를 하이브리드 방식으로 정리한다.

대사의 내용과 상황, 캐릭터, 연출 및 흐름 등을 함께 관리한다.

기존에 논의한 하이브리드 대사 시스템의 구체적인 구성은 사용자와 다시 확인한 뒤 구현한다.

## 4. 디자인

### 레퍼런스

이미지, 동영상, 텍스트 등을 자유롭게 배치하는 캔버스이다.

### 애니메이션

애니메이션 스프라이트 시트를 정리한다.

### 모델링

모델링을 배치하고 관련 요소를 정리한다.

### 사운드보드

용도별 사운드를 모아둔다.

## 5. 일반

### 빈 문서

텍스트 형식의 문서이며 이미지 삽입이 가능하다.

한글이나 워드와 같은 일반적인 문서 작성 환경을 지향한다.

텍스트와 이미지가 문서의 흐름에 맞춰 배치되는 구조이다.

자유 캔버스처럼 각 요소를 원하는 좌표에 마음대로 배치하는 방식은 아니다.

직접 그림을 그리는 기능은 제공하지 않는다.

### 메모

그림 그리기와 이미지, 동영상, 사운드, 유튜브 링크, 텍스트 등을 활용할 수 있는 자유로운 캔버스이다.

단, 위에 명시한 요소 외에는 임의로 추가할 수 없다.

빈 문서와 달리 요소를 자유롭게 배치하는 방식이다.

### 일정

일정표 템플릿이다.

### 파일 보관함

폴더 형태로 파일을 업로드하고 보관한다.

문서 추가는 불가능하며 파일 업로드만 가능하다.

# 10. 다크 모드

다크 모드는 사이트 전체에 적용되어야 한다.

일부 배경만 어둡게 바꾸는 방식으로 구현해서는 안 된다.

다음 요소를 모두 확인한다.

- 사이트 배경
- 사이드바
- 상단 메뉴
- 템플릿 배경
- 카드
- 입력창
- 버튼
- 드롭다운
- 팝업
- 모달
- 테이블
- 관계도 노드
- 연결선
- 지도 요소
- 타임라인
- 이미지 영역
- 기타 모든 템플릿별 컴포넌트

밝은 모드와 어두운 모드 모두에서 가독성을 유지해야 한다.

글자와 배경의 명도 차이를 충분히 확보한다.

다크 모드에서 특정 요소만 밝은 모드 색상으로 남아 있는 문제가 없도록 한다.

- 다크 모드 확인
- 도움말 확인
- 기존 데이터 보존 확인

### Phase 8. 최종 점검

전체 템플릿의 기능과 UI를 최종 확인한다.

미구현 기능이 있다면 명확하게 보고한다.

# 12. 테스트 기준

모든 템플릿은 다음 공통 테스트를 수행한다.

## 편집 모드 테스트

- 편집 모드 진입이 정상적으로 작동하는가?
- 텍스트 수정이 가능한가?
- 요소 추가 및 삭제가 가능한가?
- 허용된 요소의 드래그가 가능한가?
- 크기 조절 및 기타 허용된 조작이 가능한가?
- 변경 사항이 정상적으로 저장되는가?

## 보기 모드 테스트

- 보기 모드에서 텍스트가 수정되지 않는가?
- 요소를 드래그할 수 없는가?
- 요소를 삭제할 수 없는가?
- 편집 전용 컨트롤이 숨겨지는가?
- 읽기 목적의 기능은 정상적으로 작동하는가?

## 저장 테스트

- 수정 사항이 저장되는가?
- 새로고침 후에도 내용이 유지되는가?
- 문서를 다시 열어도 동일한 상태인가?
- 이미지 및 파일 연결이 유지되는가?
- 요소 위치와 크기가 유지되는가?

## 드래그 테스트

- 선택한 요소만 이동하는가?
- 의도하지 않은 요소가 함께 움직이지 않는가?
- 입력창 및 버튼과 충돌하지 않는가?
- 확대 및 축소 상태에서 정상 작동하는가?
- 저장 후 위치가 유지되는가?

## 다크 모드 테스트

- 모든 요소가 다크 모드에 대응하는가?
- 글자와 배경이 명확히 구분되는가?
- 입력창과 팝업도 정상적으로 표시되는가?
- 템플릿별 고유 요소도 정상적으로 표시되는가?

# 13. Claude / Antigravity 작업 지시 사항

다음 사항을 반드시 준수한다.

1. 기존 프로젝트 코드를 먼저 분석한다.
2. 분석 결과를 보고하고 재구축 범위를 확인받는다.
3. 기존 사용자 데이터는 절대로 임의로 삭제하지 않는다.
4. 템플릿을 하나씩 순서대로 작업한다.
5. UI를 먼저 구현한다.
6. UI가 승인되기 전에는 실제 기능을 구현하지 않는다.
7. 모든 템플릿에 공통 편집 모드 규칙을 적용한다.
8. 보기 모드에서는 모든 수정 작업을 차단한다.
9. 드래그 가능 여부는 요소별로 사용자가 지정한 규칙을 따른다.
10. 사용자가 요청하지 않은 기능을 임의로 추가하지 않는다.
11. 사용자가 결정하지 않은 설계 사항은 임의로 확정하지 않는다.
12. 미구현 기능은 반드시 시각적으로 구분한다.
13. 새 기능을 추가하거나 변경하면 도움말도 함께 수정한다.
14. 다크 모드는 사이트 전체와 모든 템플릿에 적용한다.
15. 기존 공통 UI를 불필요하게 변경하지 않는다.
16. 한 단계가 완료되면 테스트 결과를 보고하고 승인을 기다린다.

## 작업 완료 보고 형식

각 Phase 또는 개별 작업이 끝날 때 다음 내용을 보고한다.

- 수정한 파일
- 구현한 UI
- 구현한 기능
- 테스트한 항목
- 테스트 결과
- 테스트하지 못한 항목
- 미구현 기능
- 도움말 업데이트 여부
- 기존 기능에 발생한 문제 또는 회귀 여부

테스트하지 않은 기능을 정상 작동한다고 보고해서는 안 된다.

# 14. 최종 완료 조건

다음 조건을 모두 만족해야 프로젝트가 완료된 것으로 판단한다.

- 전체 템플릿 목록이 정상적으로 표시된다.
- 각 템플릿이 목적에 맞는 UI를 갖춘다.
- 모든 템플릿에서 편집 모드와 보기 모드가 구분된다.
- 보기 모드에서는 수정 작업이 불가능하다.
- 편집 모드에서는 허용된 수정 작업이 가능하다.
- 드래그 가능한 요소가 정상적으로 이동한다.
- 요소별 고정 및 편집 규칙이 지켜진다.
- 데이터가 정상적으로 저장되고 불러와진다.
- 새로고침 후에도 데이터가 유지된다.
- 디자인 프리셋이 정상적으로 작동한다.
- 다크 모드가 모든 템플릿에 적용된다.
- 도움말이 실제 기능과 일치한다.
- 미구현 기능이 명확하게 구분된다.
- 기존 사용자 데이터가 보존된다.
- 기존 공통 UI에 불필요한 문제가 발생하지 않는다.
