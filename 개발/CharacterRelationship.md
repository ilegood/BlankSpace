# Blankspace - 캐릭터 관계도 템플릿 신규 개발 지시

## 1. 개발 목표

Blankspace의 캐릭터 카테고리에 새로운 '관계도' 템플릿을 처음부터 개발한다.

캐릭터 관계도는 여러 캐릭터를 노드 형태로 배치하고, 캐릭터 사이의 관계를 연결선으로 표현하여 한눈에 파악할 수 있도록 하는 시각적 관계 관리 도구다.

단순히 캐릭터를 선으로 연결하는 기능뿐 아니라 관계의 종류, 방향, 설명, 색상 및 형태 등을 자유롭게 설정할 수 있어야 한다.

사용자가 자신의 세계관이나 작품에 맞춰 관계도를 자유롭게 구성하고 꾸밀 수 있는 커스터마이징형 템플릿을 목표로 한다.

캐릭터 관계도는 다음 두 가지 캐릭터 생성 방식을 모두 지원해야 한다.

1. 기존 캐릭터 시트에서 캐릭터를 가져오는 방식
2. 관계도 내부에서 독립적인 캐릭터를 직접 생성하는 방식

두 방식은 하나의 관계도 안에서 함께 사용할 수 있어야 한다.

**핵심 원칙은 캐릭터와 관계를 자유롭게 추가하고 연결하며, 관계도의 구조와 디자인까지 사용자가 직접 커스터마이징할 수 있도록 하는 것이다.**

# 2. 개발 진행 원칙

이번 작업은 기존 관계도 기능의 개선이 아닌 신규 개발이다.

다만 Blankspace의 기존 공통 UI와 시스템은 유지한다.

개발은 다음 순서로 진행한다.

### 1단계: UI 설계 및 구현

먼저 관계도의 전체적인 UI를 구현한다.

- 관계도 캔버스
- 캐릭터 노드
- 관계 연결선
- 캐릭터 추가 UI
- 관계 추가 UI
- 우측 편집 패널
- 상단 도구 메뉴
- 보기 모드 및 편집 모드

이 단계에서는 실제 데이터 저장이나 기능 연결을 진행하지 않는다.

UI 확인을 위한 임시 데이터는 사용할 수 있다.

### 2단계: 사용자 확인 및 승인

구현한 UI를 사용자에게 보여준다.

수정 요청이 있다면 UI를 먼저 수정한다.

사용자가 승인하기 전까지 실제 기능 구현을 시작하지 않는다.

### 3단계: 기능 구현

승인된 UI를 기준으로 실제 기능을 구현한다.

- 캐릭터 생성 및 가져오기
- 노드 이동 및 편집
- 관계 연결 및 수정
- 캔버스 조작
- 커스터마이징
- 저장 및 불러오기

### 4단계: 테스트

실제 브라우저에서 모든 기능을 테스트한다.

### 5단계: 도움말 업데이트

새롭게 추가된 관계도 기능의 사용 방법을 도움말에 반영한다.

# 3. 전체 화면 구성

관계도는 크게 세 영역으로 구성한다.

## 3-1. 상단 도구 영역

관계도를 관리하고 조작하기 위한 메뉴를 제공한다.

고려할 기능:

- 관계도 제목
- 캐릭터 추가
- 관계 추가
- 그룹 추가
- 실행 취소 및 다시 실행
- 확대 및 축소
- 화면 맞춤
- 전체 보기
- 보기 모드 및 편집 모드 전환
- 관계도 설정

불필요하게 많은 버튼을 한꺼번에 표시하지 않는다.

기능을 목적에 따라 그룹화하고 직관적으로 배치한다.

## 3-2. 중앙 캔버스

캐릭터 노드와 관계 연결선이 표시되는 메인 작업 공간이다.

캔버스는 충분한 작업 영역을 제공해야 한다.

다음 요소를 배치할 수 있어야 한다.

- 캐릭터 노드
- 관계 연결선
- 그룹 영역
- 관계 설명
- 기타 관계도 구성 요소

사용자가 원하는 위치에 캐릭터를 배치할 수 있어야 한다.

캔버스는 확대, 축소 및 이동이 가능해야 한다.

## 3-3. 우측 편집 패널

선택한 요소의 정보를 확인하고 편집하는 영역이다.

선택한 요소의 종류에 따라 표시되는 설정이 달라져야 한다.

예를 들어 캐릭터 노드를 선택하면 캐릭터 정보와 노드 디자인을 표시하고, 관계선을 선택하면 관계 정보와 연결선 디자인을 표시한다.

아무 요소도 선택하지 않았다면 전체 관계도의 설정을 표시한다.

# 4. 캐릭터 노드 시스템

캐릭터 노드는 관계도에서 캐릭터를 표현하는 기본 구성 요소다.

각 캐릭터는 독립적인 노드로 표시된다.

## 4-1. 캐릭터 생성 방식

다음 두 가지 방식을 모두 지원한다.

### A. 캐릭터 시트에서 가져오기

기존 Blankspace 캐릭터 시트에 등록된 캐릭터를 관계도에 추가할 수 있어야 한다.

지원할 기능:

- 기존 캐릭터 목록 확인
- 캐릭터 검색
- 캐릭터 선택
- 선택한 캐릭터를 관계도에 추가
- 동일한 캐릭터 중복 추가 방지
- 여러 캐릭터 선택 및 추가

캐릭터 시트에서 가져온 노드는 원본 캐릭터 시트와 연결 관계를 유지해야 한다.

캐릭터의 이름이나 대표 이미지 등 연동하기로 한 정보가 원본에서 변경되면 관계도에도 최신 정보가 반영되도록 설계한다.

단, 관계도에서 노드의 위치나 디자인을 변경한다고 해서 원본 캐릭터 시트의 데이터가 변경되어서는 안 된다.

관계도에서 캐릭터의 기본 정보를 직접 수정하는 기능은 원본 데이터에 영향을 줄 수 있으므로 별도로 구분한다.

원본 캐릭터 시트를 수정해야 하는 경우 해당 문서로 이동할 수 있는 기능을 제공한다.

### B. 관계도 내부에서 직접 생성

캐릭터 시트를 만들지 않은 캐릭터도 관계도 안에서 직접 생성할 수 있어야 한다.

지원할 정보:

- 캐릭터 이름
- 대표 이미지
- 간단한 설명
- 기타 사용자 정의 정보

필요한 경우 직접 생성한 캐릭터도 추가 정보를 작성할 수 있도록 한다.

이 방식으로 생성한 캐릭터는 관계도 내부에서 독립적으로 관리한다.

캐릭터 시트가 존재하지 않는다는 이유로 생성이나 관계 연결이 제한되어서는 안 된다.

### C. 두 방식의 혼합 사용

하나의 관계도 안에서 캐릭터 시트에서 가져온 캐릭터와 직접 생성한 캐릭터를 함께 사용할 수 있어야 한다.

두 종류의 노드는 동일한 방식으로 관계를 생성하고 관리할 수 있어야 한다.

단, 원본 캐릭터 시트와 연결된 캐릭터인지 독립적으로 생성된 캐릭터인지는 내부 데이터에서 구분해야 한다.

# 5. 캐릭터 노드 커스터마이징

사용자가 캐릭터 노드의 표시 방식과 디자인을 자유롭게 변경할 수 있어야 한다.

## 5-1. 노드 표시 정보

노드에 표시할 정보를 선택할 수 있어야 한다.

기본적으로 다음 항목을 고려한다.

- 대표 이미지
- 캐릭터 이름
- 별명
- 간단한 설명
- 소속
- 기타 사용자 정의 정보

모든 정보를 반드시 표시할 필요는 없다.

사용자가 원하는 정보만 선택하여 노드에 표시할 수 있어야 한다.

## 5-2. 노드 디자인

다음 항목을 변경할 수 있어야 한다.

- 노드 크기
- 노드 모양
- 배경색
- 테두리 색상
- 테두리 두께
- 모서리 둥글기
- 이미지 표시 여부
- 이미지 영역 크기
- 글꼴
- 글자 크기
- 글자 색상
- 텍스트 정렬

노드 디자인은 캐릭터별로 개별 설정할 수 있어야 한다.

## 5-3. 노드 관리

- 노드 추가
- 노드 삭제
- 노드 복제
- 노드 선택
- 노드 이동
- 노드 크기 조절
- 노드 정렬
- 노드 앞뒤 배치 순서 변경

노드를 이동하면 연결된 관계선도 함께 이동해야 한다.

노드 삭제 시 연결된 관계선을 어떻게 처리할지 사용자에게 명확하게 안내한다.

노드 삭제가 원본 캐릭터 시트의 삭제로 이어져서는 안 된다.

# 6. 관계 연결 시스템

캐릭터 관계도의 가장 중요한 기능이다.

두 캐릭터 노드를 연결하여 관계를 표현할 수 있어야 한다.

관계선은 단순한 장식이 아니라 독립적인 데이터로 관리한다.

## 6-1. 관계 생성

사용자가 두 캐릭터를 선택하거나 연결 도구를 사용하여 관계를 생성할 수 있도록 한다.

관계 생성 시 다음 정보를 설정할 수 있어야 한다.

- 관계 대상 캐릭터 A
- 관계 대상 캐릭터 B
- 관계 이름
- 관계 설명
- 관계 방향
- 관계 상태
- 관계선 색상
- 관계선 형태

관계가 생성되면 두 캐릭터 사이에 연결선이 표시되어야 한다.

## 6-2. 관계 방향

관계는 다음 유형을 지원한다.

### 양방향 관계

두 캐릭터 사이의 관계를 하나의 연결선으로 표현한다.

예시:
- 친구
- 가족
- 동료
- 연인

### 단방향 관계

한 캐릭터에서 다른 캐릭터로 향하는 방향을 표현한다.

예시:
- A가 B를 존경함
- A가 B를 짝사랑함
- A가 B를 경계함
- A가 B를 추적함

단방향 관계는 화살표 등으로 방향을 명확하게 표현한다.

## 6-3. 다중 관계

두 캐릭터 사이에 여러 관계가 동시에 존재할 수 있어야 한다.

예를 들어 A와 B가 친구이면서 라이벌일 수도 있다.

따라서 두 노드 사이에 관계를 하나만 생성하도록 제한하지 않는다.

여러 관계가 존재하는 경우 연결선이 서로 겹쳐 구분되지 않는 문제를 방지해야 한다.

필요하면 곡선 연결선이나 평행 연결선을 활용한다.

각 관계는 개별적으로 선택하고 수정할 수 있어야 한다.

## 6-4. 관계 관리

- 관계 추가
- 관계 삭제
- 관계 이름 변경
- 관계 설명 변경
- 관계 방향 변경
- 관계 상태 변경
- 관계선 색상 변경
- 관계선 형태 변경
- 관계선 두께 변경

관계선의 끝점은 연결된 캐릭터 노드에 정확하게 연결되어야 한다.

노드를 이동하거나 크기를 변경해도 연결이 유지되어야 한다.

# 7. 관계선 디자인 커스터마이징

관계선은 사용자가 관계의 종류를 시각적으로 구분할 수 있도록 다양한 표현을 지원해야 한다.

## 7-1. 선 형태

다음 형태를 고려한다.

- 실선
- 점선
- 파선
- 화살표가 있는 선
- 양쪽 화살표가 있는 선

## 7-2. 선 디자인

- 선 색상
- 선 두께
- 선 투명도
- 선 모양
- 곡선 여부
- 화살표 디자인

## 7-3. 관계 라벨

관계선에 관계 이름이나 간단한 설명을 표시할 수 있어야 한다.

예시:

- 친구
- 적대 관계
- 짝사랑
- 상하 관계
- 가족

라벨은 사용자가 표시 여부를 선택할 수 있어야 한다.

관계선과 라벨이 다른 노드나 관계선과 겹쳐 읽기 어려워지는 문제를 방지한다.

# 8. 그룹 시스템

여러 캐릭터를 그룹으로 분류할 수 있는 기능을 제공한다.

예시:

- 가족
- 왕국
- 조직
- 길드
- 학교
- 종족
- 세력

그룹은 캐릭터 노드를 시각적으로 구분하기 위한 용도로 사용한다.

## 8-1. 그룹 관리

- 그룹 추가
- 그룹 삭제
- 그룹 이름 변경
- 그룹 색상 변경
- 그룹 내부 캐릭터 관리
- 그룹 접기 및 펼치기

하나의 캐릭터가 여러 그룹에 소속될 수 있는 구조도 고려한다.

그룹은 관계도에서 캐릭터를 구분하는 보조 기능이며, 캐릭터 간 관계 연결과는 별도로 관리한다.

## 8-2. 그룹 표시 방식

다음 표시 방식을 고려한다.

- 그룹 영역을 배경으로 표시
- 그룹별 색상 구분
- 그룹 이름 표시
- 그룹별 캐릭터 접기 및 펼치기

그룹 영역은 캐릭터 노드와 관계선을 가리지 않도록 구성한다.

# 9. 캔버스 조작

관계도는 넓은 공간에 많은 캐릭터와 관계선을 배치할 수 있어야 한다.

다음 기능을 제공한다.

- 캔버스 확대
- 캔버스 축소
- 화면 이동
- 전체 화면 맞춤
- 선택한 노드로 화면 이동
- 전체 관계도 보기
- 캔버스 위치 초기화

마우스 휠을 활용한 확대 및 축소를 고려한다.

캔버스 이동과 노드 드래그가 충돌하지 않도록 조작 방식을 명확하게 구분한다.

확대 및 축소를 하더라도 노드와 관계선의 연결 상태가 유지되어야 한다.

노드가 많아져도 관계도를 확인하고 조작하기 편리해야 한다.

---

# 10. 레이아웃 및 배치 커스터마이징

사용자는 캐릭터 노드의 배치를 자유롭게 변경할 수 있어야 한다.

기본적으로 수동 배치를 제공한다.

추가로 다음 기능을 고려한다.

- 선택한 노드 정렬
- 여러 노드 간격 맞추기
- 가로 정렬
- 세로 정렬
- 그룹별 정렬
- 자동 배치
- 자동 배치 후 수동 수정

자동 배치는 노드가 많을 때 초기 배치를 돕는 보조 기능이다.

자동 배치가 사용자가 직접 구성한 위치를 임의로 덮어쓰지 않도록 한다.

자동 배치 실행 전에 기존 위치가 변경된다는 점을 명확하게 안내한다.

---

# 11. 우측 편집 패널

선택한 요소에 따라 우측 편집 패널의 내용이 달라져야 한다.

## 11-1. 캐릭터 노드 선택 시

- 캐릭터 이름
- 대표 이미지
- 간단한 설명
- 노드 표시 정보
- 노드 크기
- 노드 모양
- 배경색
- 테두리
- 글꼴
- 글자 크기
- 글자 색상
- 정렬

캐릭터 시트에서 가져온 노드는 원본과 연결된 정보인지 확인할 수 있어야 한다.

## 11-2. 관계선 선택 시

- 연결 대상 캐릭터
- 관계 이름
- 관계 설명
- 관계 방향
- 관계 상태
- 선 색상
- 선 형태
- 선 두께
- 화살표 설정
- 라벨 표시 여부

## 11-3. 그룹 선택 시

- 그룹 이름
- 그룹 색상
- 그룹 표시 방식
- 그룹 내부 캐릭터 관리

## 11-4. 아무 요소도 선택하지 않은 경우

전체 관계도 설정을 표시한다.

- 캔버스 배경

- 기본 관계선 디자인
- 전체 색상
- 기본 글꼴
- 전체 레이아웃 설정

# 12. 전체 관계도 디자인 커스터마이징

관계도 전체의 시각적 디자인을 변경할 수 있어야 한다.

다음 항목을 고려한다.

- 캔버스 배경색
- 배경 패턴
- 기본 노드 디자인
- 기본 관계선 색상
- 기본 글꼴
- 전체 글자 크기
- 그룹 색상
- 연결선 투명도
- 전체 간격

사용자가 관계도의 분위기를 자신의 작품에 맞게 변경할 수 있도록 한다.

예를 들어 밝고 귀여운 관계도부터 어둡고 진지한 분위기의 관계도까지 만들 수 있어야 한다.

다크 모드에서도 모든 요소가 정상적으로 표시되어야 한다.

단, 관계도에는 현재 별도의 디자인 프리셋을 적용하지 않는다.

---

# 13. 관계도 저장 및 사용자 정의 구성

관계도는 문서별로 독립적으로 관리되어야 한다.

저장해야 할 정보는 다음과 같다.

### 캐릭터 노드 데이터
- 노드 ID
- 캐릭터 데이터 출처
- 연결된 캐릭터 시트 ID
- 노드 위치
- 노드 크기
- 노드 표시 정보
- 노드 디자인

### 관계 데이터
- 관계 ID
- 연결 대상 노드 ID
- 관계 이름
- 관계 설명
- 관계 방향
- 관계 상태
- 관계선 디자인

### 그룹 데이터
- 그룹 ID
- 그룹 이름
- 그룹 색상
- 그룹에 속한 노드 정보
- 그룹 표시 설정

### 캔버스 데이터
- 캔버스 위치
- 확대 및 축소 상태
- 배경 디자인
- 전체 레이아웃

캐릭터 시트에서 가져온 노드는 원본 문서 ID를 참조하는 방식으로 관리한다.

관계도 내부에서 직접 생성한 캐릭터는 관계도 내부 데이터로 관리한다.

노드의 위치와 디자인은 원본 캐릭터 시트의 데이터와 분리한다.

새로고침 후에도 모든 노드와 관계선, 그룹, 위치 및 디자인 설정이 유지되어야 한다.

관계도는 여러 요소를 이동하고 연결하는 작업이 많으므로 실행 취소 및 다시 실행 기능을 고려한다.

다음 작업을 취소하고 다시 실행할 수 있도록 설계한다.

- 노드 추가 및 삭제
- 노드 이동
- 노드 크기 변경
- 관계 추가 및 삭제
- 관계 정보 변경
- 그룹 추가 및 삭제
- 디자인 변경

단, 실행 취소와 다시 실행이 저장 시스템과 충돌하지 않도록 한다.

# 16. 데이터 안정성 및 기존 시스템 연동

관계도는 Blankspace의 공통 저장 시스템을 사용한다.

다음 사항을 준수한다.

- 기존 IndexedDB 저장 구조와 호환성 확인
- 관계도 데이터의 독립적인 저장
- 노드와 관계 데이터 간 참조 무결성 유지
- 연속 저장 시 데이터 덮어쓰기 방지
- 실제 저장 성공 여부 확인
- 저장 실패 시 사용자에게 안내
- 새로고침 이후 데이터 유지

캐릭터 시트에서 가져온 캐릭터는 원본 문서를 삭제하거나 수정하지 않는다.

관계도에서 노드를 삭제하더라도 원본 캐릭터 시트는 유지되어야 한다.

원본 캐릭터 시트가 삭제되거나 접근할 수 없는 상태가 되었을 때 관계도에 남아 있는 노드의 처리 방식도 고려한다.

원본 데이터가 사라졌다는 이유로 관계도에 저장된 관계 정보까지 임의로 삭제해서는 안 된다.

# 19. 작업 시 주의사항

1. 관계도는 신규 개발이므로 기존에 없는 기능을 구현해도 된다.
2. 기존 Blankspace의 공통 UI와 전체적인 디자인을 유지한다.
3. 모든 편집 기능은 편집 모드에서만 작동한다.
4. 캐릭터 시트 연동과 독립 캐릭터 생성을 모두 지원한다.
5. 두 종류의 캐릭터를 하나의 관계도에서 함께 사용할 수 있어야 한다.
6. 관계는 노드와 별도의 독립적인 데이터로 관리한다.
7. 두 캐릭터 사이에 여러 관계가 존재할 수 있어야 한다.
8. 관계의 방향을 표현할 수 있어야 한다.
9. 노드 이동 시 연결선이 정상적으로 따라와야 한다.
10. 관계도에서 원본 캐릭터 시트의 데이터가 임의로 변경되면 안 된다.
11. 사용자가 요청하지 않은 기능을 임의로 추가하지 않는다.
12. 저장 및 불러오기 기능은 실제 브라우저에서 테스트한다.
13. 테스트하지 않은 기능을 정상 작동한다고 보고하지 않는다.
