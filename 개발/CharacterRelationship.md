# 캐릭터 관계도 UI 디자인 수정 지시

## 1. 디자인 방향

캐릭터 관계도는 일반적인 조직도나 카드형 네트워크가 아닌, 여러 캐릭터의 초상화를 캔버스에 자유롭게 배치하고 캐릭터 사이의 관계를 다양한 색상의 곡선으로 연결하는 형태로 디자인한다.

참고 이미지와 같이 캐릭터들이 원형 또는 타원형으로 배치된 구성을 기본적인 디자인 예시로 사용한다.

단, 원형 배치는 기본 레이아웃일 뿐이며 사용자가 캐릭터를 원하는 위치로 자유롭게 이동할 수 있어야 한다.

전체적인 디자인은 깔끔하고 직관적인 그래픽 편집 도구 형태로 제작한다.

## 2. 중앙 캔버스

관계도의 가장 중요한 영역이다.

- 화면 중앙 대부분을 차지하는 넓은 작업 영역으로 구성한다.
- 밝은 배경을 기본으로 하며 은은한 격자 패턴을 사용할 수 있다.
- 캐릭터를 원형 초상화 형태로 표시한다.
- 캐릭터는 원형, 타원형 등으로 표현할 수 있으며 초상화가 프레임 안에 자연스럽게 들어가도록 한다.
- 캐릭터의 이름이나 추가 정보는 선택적으로 표시할 수 있도록 한다.
- 캐릭터 사이의 관계선은 초상화 주변에서 시작하고 끝나도록 연결한다.
- 관계선이 캐릭터 이미지나 이름을 가리지 않도록 한다.
- 관계선은 직선이 아닌 곡선 형태를 기본으로 사용한다.
- 관계가 많아 여러 선이 교차하더라도 관계를 구분할 수 있도록 곡률, 연결 위치, 선의 형태를 조절할 수 있어야 한다.

## 3. 캐릭터 배치

캐릭터 초상화는 관계도에서 가장 중요한 시각적 요소다.

- 원형 초상화 형태를 기본으로 한다.
- 캐릭터 이미지가 없으면 기본 프로필 이미지를 표시한다.
- 캐릭터마다 테두리 색상, 굵기, 크기를 설정할 수 있다.
- 캐릭터를 드래그하여 자유롭게 이동할 수 있다.
- 캐릭터 크기를 개별적으로 조절할 수 있다.
- 여러 캐릭터를 원형으로 배치하거나 특정 캐릭터를 중심으로 배치할 수 있다.
- 캐릭터가 많아져도 캔버스가 제한되지 않도록 확대, 축소, 이동을 지원한다.
- 캐릭터 선택 시 선택 상태가 명확하게 보이도록 테두리나 강조 효과를 적용한다.

## 4. 관계선 디자인

관계선은 캐릭터 관계도의 핵심 요소다.

관계 종류에 따라 색상을 다르게 설정하고, 관계선의 색상과 범례가 서로 일치해야 한다.

기본 관계 유형은 다음과 같이 구성한다.

- 최애 커플링: 빨간색
- 선호하는 커플링: 주황색
- 좋아하는 커플링: 파란색
- 존경 / 신뢰: 초록색
- 지뢰 / 적대: 보라색
- 복잡한 관계: 회색 또는 보라색 점선

위 색상과 명칭은 기본 예시이며 사용자가 직접 관계 유형과 색상을 추가하거나 수정할 수 있어야 한다.

### 관계선 표현 방식

- 기본적으로 부드러운 곡선으로 연결한다.
- 단방향과 양방향 연결을 지원한다.
- 화살표의 방향을 시각적으로 구분할 수 있어야 한다.
- 점선과 실선을 선택할 수 있어야 한다.
- 선의 굵기와 색상을 변경할 수 있어야 한다.
- 관계선 위에 관계 이름이나 짧은 라벨을 표시할 수 있어야 한다.
- 관계선이 겹치는 경우 서로 구분할 수 있도록 곡선의 휘어짐과 연결 위치를 조정할 수 있어야 한다.
- 동일한 두 캐릭터 사이에 여러 개의 서로 다른 관계선을 연결할 수 있어야 한다.

### 관계선의 자유로운 편집

- 두 캐릭터를 선택하여 관계선을 생성한다.
- 관계선의 양 끝점을 다른 캐릭터에 다시 연결할 수 있다.
- 관계선의 곡률과 경로를 조절할 수 있다.
- 관계선의 위치를 변경해 다른 관계선과의 겹침을 줄일 수 있다.
- 관계선을 선택하면 해당 선만 강조 표시한다.

## 5. 관계 범례 및 스타일 커스터마이징

관계 범례는 사용자가 자유롭게 추가하고 수정할 수 있는 독립적인 설정 시스템으로 제작한다.

기본 관계 유형은 예시로 제공하되, 색상과 이름을 고정하지 않는다.

### 5-1. 관계 유형 관리

각 관계 범례 항목은 다음 속성을 가진다.

- 관계 이름: 자유롭게 입력하고 수정 가능
- 대표 색상: 색상 선택기를 통해 자유롭게 변경 가능
- 선 스타일: 단색, 그라데이션, 점선, 대시선 등 선택 가능
- 선 굵기: 자유롭게 조절 가능
- 그라데이션 설정: 시작 색상, 종료 색상, 중간 색상 추가 및 수정 가능
- 그라데이션 방향: 선의 진행 방향, 반대 방향 등 설정 가능

### 5-2. 그라데이션 관계선

관계선에 단색뿐만 아니라 그라데이션을 적용할 수 있도록 한다.

지원해야 할 스타일:

1. 단색: 하나의 색상으로 선 전체를 표현
2. 2색 그라데이션: 시작 색상에서 종료 색상으로 자연스럽게 변화
3. 다중 그라데이션: 여러 색상 지점을 추가하여 복수의 색상이 연결되는 형태
4. 점선: 일정한 간격으로 선이 끊기는 형태
5. 대시선: 길이가 있는 선과 간격이 반복되는 형태
6. 그라데이션 점선: 점선의 각 구간에 그라데이션을 적용하는 형태
7. 그라데이션 대시선: 대시 구간에 그라데이션을 적용하는 형태

그라데이션 편집 UI에는 다음 기능을 제공한다.

- 색상 지점 추가 및 삭제
- 각 색상 지점의 색상 변경
- 색상 지점의 위치 조절
- 그라데이션 방향 변경
- 실시간 미리보기

### 5-3. 범례와 관계선의 연동

범례 항목을 수정하면 해당 유형을 사용하는 모든 관계선에 변경 사항이 반영되어야 한다.

예를 들어 '최애 커플링'의 색상을 빨간색에서 분홍색으로 변경하면, 해당 범례를 사용하는 모든 관계선이 자동으로 분홍색으로 변경되어야 한다.

관계선 개별 설정을 통해 범례의 기본 스타일을 일시적으로 덮어쓸 수 있는지도 고려하되, 기본적으로 범례와 관계선의 스타일은 연동되어야 한다.

### 5-4. 범례 표시 및 배치

- 범례의 위치를 자유롭게 이동할 수 있다.
- 범례의 표시 및 숨기기를 지원한다.
- 범례 항목의 순서를 변경할 수 있다.
- 범례 항목을 추가하거나 삭제할 수 있다.
- 범례 항목의 이름과 색상 미리보기를 함께 표시한다.
- 범례 항목을 클릭하면 해당 관계 유형을 사용하는 관계선을 강조할 수 있다.

### 5-5. 저장 및 데이터 관리

- 범례 설정은 관계도별로 독립 저장한다.
- 관계 이름, 색상, 그라데이션, 선 스타일, 굵기, 순서 등을 모두 저장한다.
- 새로고침 후에도 설정이 유지되어야 한다.
- 범례 항목을 삭제할 때 기존 관계선의 처리 방식을 사용자에게 안내한다.
- 기존 관계선의 스타일이 의도치 않게 초기화되거나 손실되지 않도록 한다.

## 6. 전체 UI 구성

### 상단 툴바
- 관계도 이름
- 실행 취소 / 다시 실행
- 선택 도구
- 캔버스 이동 도구
- 관계선 생성 도구
- 텍스트 추가 도구
- 확대 / 축소
- 화면 맞춤
- 보기 모드 / 편집 모드 전환

### 좌측 패널
- 캐릭터 목록
- 캐릭터 검색
- 캐릭터 시트에서 가져오기
- 관계도 내부에서 직접 캐릭터 생성
- 캐릭터 목록에서 캔버스로 드래그하여 배치
- 그룹 목록

### 중앙 캔버스
- 원형 캐릭터 초상화
- 자유로운 캐릭터 배치
- 다양한 색상의 관계선
- 관계 라벨
- 관계 범례
- 확대 / 축소 및 이동

### 우측 속성 패널
선택한 요소에 따라 속성을 변경할 수 있도록 한다.

캐릭터 선택 시:
- 이미지
- 이름
- 크기
- 테두리 색상
- 표시 정보

관계선 선택 시:
- 관계 이름
- 관계 설명
- 관계 유형
- 선 색상
- 선 스타일
- 선 굵기
- 관계 방향
- 라벨 표시 여부

캔버스 선택 시:
- 배경색
- 격자 표시
- 기본 캐릭터 스타일
- 기본 관계선 스타일

## 7. 디자인에서 반드시 지켜야 할 사항

- 관계도를 카드형 프로필 목록처럼 디자인하지 않는다.
- 캐릭터 초상화가 중심이 되는 관계도 형태를 유지한다.
- 관계선이 화면의 주요 시각적 요소가 되도록 한다.
- 원형 배치는 예시이며 강제하지 않는다.
- 캐릭터와 관계선 모두 자유롭게 편집할 수 있어야 한다.
- 관계가 많아도 시각적으로 구분할 수 있는 구조를 만든다.
- 사용자가 직접 관계 유형과 색상을 정의할 수 있도록 한다.
- 지나치게 많은 장식이나 불필요한 UI를 추가하지 않는다.
- 기존 Blankspace의 전체적인 UI와 디자인 시스템은 유지한다.
- 다크 모드에서도 캐릭터 초상화와 관계선, 범례가 명확하게 구분되도록 한다.

## 8. 작업 진행 방식

이번 작업에서는 우선 위 내용을 바탕으로 관계도 UI 디자인만 구현한다.

아직 실제 관계 생성, 캐릭터 데이터 연결, 저장 기능 등의 동작은 구현하지 않는다.

UI 구현이 끝나면 브라우저에서 직접 확인할 수 있도록 하고, 사용자에게 검토를 요청한다.

사용자가 디자인을 승인한 이후에 실제 기능을 단계별로 구현한다.
